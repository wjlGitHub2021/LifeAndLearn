# 本地运行手册

> 2026-09-27 在 macOS、Node.js 22.22.3 和 npm 上验证。仅监听 `127.0.0.1`，未部署公网。

## 安装与启动

在项目根目录执行：

```sh
rtk npm install --no-audit --no-fund
rtk npm run dev
```

浏览器打开 `http://127.0.0.1:3000`。开发服务用终端 `Ctrl+C` 停止。生产模式先执行 `rtk npm run build`，再执行 `rtk npm run start`；本机曾以 `-p 3002` 参数成功完成生产冒烟检查。类型和自动化检查分别为 `rtk npm run typecheck`、`rtk npm test`。

新版首页先显示一件最需要处理的事项及下一动作；如果没有待处理事项，会显示计划日或截止日最早的进行中事项。顶部列待处理、实际正在运行和已安排计划日的真实数量；右侧只列未在主焦点/队列出现的后续安排和协作提醒。空库只有一处轻量新建，右侧说明从需求、Agent 到成果的路径。点击侧栏「新建事项」或首页入口，先填写要完成的事，再展开求职/英语预设或自选 Agent 配置。预设路径的「补充资料」可留空：没有简历、岗位描述或词表也可先做通用准备，个性化事实与需要准确来源的内容仍须核对。可调整角色与时间，保存后查看分工；自选路径把需求草稿带入步骤编辑器。两类事项均需保存后手动启动模型。首页队列和“我的事项”汇总两类事项；“我的事项”按待我处理、其他进行中和历史分组，可按关键词、参与方式和日期筛选，每页最多显示 10 条。桌面选择行后右侧预览，窄屏点击整行直接打开原详情；预设的资料权限、职责和有效偏好以「Agent 团队」配置为准，资料与偏好在「资料与记忆」按来源查看。

同日的其他安排会在首页紧凑队列提示。快捷事项已有成果可练习时，顶部「当前要做的事」也提供开始或继续练习入口；自定义 Agent 运行失败时，最近一次对应步骤的原因显示在主操作旁，详细来源仍在侧栏。模型内容过长时可先从顶部行动，再按需阅读成果。

自定义链路先在「Agent 团队」创建 Agent，可从空白或求职/英语模板填写名称、职责、交付物，并选择是否允许读取事项资料和已选上游成果；保存后可立即选择。暂停的 Agent 不接新运行，恢复后仍需手动启动。每个实例的偏好单独保存、编辑或撤销。自选 Agent 事项填写需求与必要资料，依次选一至四个步骤；每一步可勾选较早步骤的成果作为输入。保存后主区域先显示运行状态、可执行操作与成果；右侧可查步骤、排期和来源，修改步骤用标题处「编辑事项」。窄屏用「事项信息」展开侧栏，Escape 关闭。无模型连接时，点击顶部连接状态或「设置」，在弹窗的模型连接区连接渠道。

「设置」有使用偏好、外观、模型连接、数据与隐私、使用说明五类。默认打开页面与日程周/月选择仅保存在当前浏览器，下次打开生效；主题沿用原浏览器偏好。数据与隐私页显示当前库的真实事项、Agent 和偏好数量，并指向所属管理页面；它没有批量清除或导出按钮。模型 API Key 只保留在后端内存，重启服务后需重新连接。

模型连接可选择原 DeepSeek、OpenAI、OpenRouter 或自定义 OpenAI 兼容公网 HTTPS 地址。每条连接输入自己的 API Key，验证时读取该 Key 可访问的 `/models`；若供应商没有该接口，返回 404/405 时可填写手动模型标识，后续生成仍须核对。连接后在同页选择工作区默认模型；「Agent 团队」中选中实例可覆盖模型或恢复跟随默认。每一步运行时依当前 Agent 选择调用，切换不重写历史，断开不会自动换厂商。账号登录目前未接入；ChatGPT 订阅不能代替 OpenAI API Key。重新启动后连接配置仍在，但每条 Key 须在本机页面重新输入。

新建快捷或自选 Agent 事项时，需求框下的「本事项模型」默认跟随参与 Agent；可改选当前已连接的一个渠道/模型，使该事项全部步骤和快捷练习都使用它。保存后仍可在事项详情调整，变更只影响后续运行，运行中不可改。若固定选择断线，详情会保留原模型并阻止启动；重新连接或明确改选后再手动启动，不会暗中切到其他模型。无可用模型时可从选择器前往「模型连接」。

「Agent 团队」先显示创建入口和可执行实例，之后展示近 7 天仅统计自定义 Agent 事项的运行与已确认成果；点击数字查看对应记录，点实例的「查看详情」查看参与事项、历史事件、当时配置与来源。大量历史分批加载。若想接着做另一件事，先在原自选 Agent 事项核对一份成果，再点「以这份已确认成果新建后续事项」；核对固定来源与版本，选择接收 Agent，并逐步勾选是否发送该成果。目标标签只用于整理，不发送到模型。来源更新后，新事项仍引用所选旧版本；可在事项详情明确修改或取消接续。

「日程与数据」可按本机日期切换周/月、前后周期与选中日，选中日只列计划在该日的快捷事项和 Agent 事项。顶部区分所选周期计划件数、全部进行中未安排和截止逾期；周视图七天直接选择。右侧（窄屏下方）可切所选日、未安排与截止逾期事项，清单内「设置排期」展开原编辑器；新建表单和事项详情也能改期。仅有截止日的开放事项仍在未安排区；截止逾期只显示提示，不自动运行。「查看数据与分布」展开后，环形图统计全部进行中事项的已安排/未安排占比，点击图例可查看对应事项；每日柱图统计所选周/月未归档事项的计划件数，可查看文字数据。图表只反映真实站内记录，不表示学习效果。排期保存使用独立修订，发生 409 时核对最新安排再选择保留草稿或载入最新。Agent 团队另有基于真实事件的 7/30 天折线趋势，可切换启动、成功、失败运行和已确认成果；其滚动 24 小时窗口不等同于日历周/月，点区间可读取对应事件。

成果可逐步核对；事实纠正会让受影响成果待更新，旧版本留在独立的“全部成果历史”，即使移除或重排步骤仍能查看生成时的角色、步骤和上游版本。切换事项或返回新建后，未保存的纠正按原事项保留；保存时继续输入的新增草稿不会被迟到的成功响应清除。失败、中断或取消后手动继续，不自动重发；主动取消不列首页告警，配置变化导致的取消列为待处理。事项可完成、归档、重新打开。编辑 Agent 配置或暂停会阻止旧运行结果提交；仅暂停自建 Agent 时，开放事项中已生成且内容依据未变的成果仍可核对，恢复后不用重生。已完成事项的已确认成果仍可查看。此链路当前先交付事项成果，不包含旧快捷事项中的专用英语练习；两条路径的数据及历史分别保留。

持续事项先看首页“现在需要你处理”：待核对、待继续、待回答、失败和中断均有详情入口；没有这类事项时显示计划日或截止日最早的进行中事项。快捷事项详情以「现在做」为默认页，待答题目、选择与理由或开放回答、提交入口只在这张主卡出现；模型反馈也在这里阅读。「成果」「练习记录」按需切换，历史中的输入依据默认折叠，长需求标题可展开。成果可逐份确认；所有当前角色成果均有效且确认后可完成事项，也可归档，之后从“我的事项”历史重新打开。主动取消会保留记录，但不会自动当成首页告警。详情右侧可查看排期、分工和运行来源；点击标题旁「编辑事项」展开需求、角色、资料、英文专用要求、时间和优先级，运行中先取消再改。调整时间或优先级保留有效成果，修改英文专用要求只使英语成果待更新。移除角色后，其旧成果与练习仍在详情历史中。

同一快捷事项可在当前成果上“开始练习”：模型先准备 Markdown 题目；选择题显示独立选项和理由框，开放题显示回答框，用户实际作答后再点击“提交回答并获取反馈”；反馈和下一轮建议会保存。成果、出题及反馈运行中，主卡显示模型已返回的正文增量；模型确实返回思考字段时可在独立区查看，预览不是最终成果。下一轮引用同一当前成果、同一预设配置修订下的旧轮次，以及用户明确关联的跨事项来源；修改或清空资料、收紧权限并重生成果后，未显式关联的旧练习仍可查看，但不会进入新请求。题目准备、成果生成都不代表用户已完成练习。刷新前未提交的回答会触发离开提醒；建议先提交，不能依赖浏览器保留草稿。模型失败、取消、中断或角色暂停后由用户查看原因并手动恢复，不自动重复调用。

跨天继续快捷事项时，先在前一事项确认成果，再打开后一天事项的右侧「接续上一件事」，选择已确认的快捷或自定义 Agent 成果，预览后点击「关联并更新成果」。旧成果保留为历史，手动重新启动后才把固定来源快照发送给模型。快捷来源若有当前成果下已完成练习，会连同真实作答、反馈和建议带入；没有完成记录就不显示练习进步。后续可重新关联更新版本，或移除来源。来源链最多七段；关闭参与角色的上游权限后，须恢复权限或移除来源才能运行。

新版「资料与记忆」按事项资料、明确纠正、可接续成果和长期偏好四类查找。前三类可按所属事项类型筛选并在本地搜索标题与正文，结果行显示命中片段；右侧阅读 Markdown、来源事项、参与 Agent 当前权限与使用范围，可打开原事项维护。没有原始资料但有当前已确认成果的事项也会出现在成果类；历史旧版本不标为可接续。快捷事项纠正只显示“已记录”，自定义纠正按真实有效/停用状态显示。长期偏好按 Agent 查看，有效偏好可保存、编辑、撤销，已撤销项留在历史区；切换 Agent 的未保存输入会分别保留。此页没有独立文件上传，也不会自动把原始资料共享给其他事项；已确认成果仍须在新事项的接续区明确选择和预览。旧版记忆有记录时才显示原记录入口。

旧目标、练习和反馈记录从侧栏“旧版记录”进入 `/legacy`，旧页可返回新版。旧版记录没有被伪造为新版事项。以下目标和今日安排操作只适用于旧版页面。

首次使用和以后新增目标，都从“今天”的“新增目标”或左侧“目标”入口进入：选择英语学习或求职准备，填写名称、优先级及该任务必要的资料，点击“保存目标”。目标可反复新增；已完成任务不会锁住目标表单。目标列表的“暂停后续安排”可阻止某个目标进入后续预览，适合把验收用的测试目标排除；关闭后目标及历史任务仍保留，已有待办只有在采用新安排后才会调整。

返回“今天”，设置今天可用的**总**分钟数，点击“预览今日安排”，核对各目标、任务内容和时间后点击“采用安排”。预览不改变现有任务；新增目标也不会自动生成任务。已开始或完成的任务仍占用今日预算：若已经安排 40 分钟，想在今天追加一项至少 10 分钟的任务，总预算需设为至少 50 分钟。今天页分别显示待处理和已完成的任务。

目前目标领域只支持英语学习和求职准备。具体练习题由规则产生，用户可以控制目标是否参与、优先级和总时间，并决定是否采用预览；目前不能手工编写或修改单项今日任务。

同一目标再次预览时，任务会参考该目标的已采用或纠正记忆、角色训练偏好和上次反馈建议；未采用的建议会明确标出。目标改为口语后，与口语冲突的旧作文要求不会进入新任务或模型反馈。口语练习需要先口头回答，再把回答转写到作答框；当前不能收录或评价声音。若目标明确要求纯语音且拒绝文字转写，预览会提示无法安排。

需要旧版模型反馈时，从顶部连接状态进入模型连接页，输入所选渠道的 Key 并选默认模型；逐 Agent 的覆盖在新版团队页设置，然后在旧任务中提交自己的回答。Key 不要放入终端命令、聊天、源码或数据库。连接验证只检查模型列表；提交一次任务才触发一次生成。DeepSeek 下拉菜单仍显示展示名与括号中的实际 API 请求标识，例如 DeepSeek-V4.1-Flash (`deepseek-flash`)。此前 DeepSeek 虚构数据真实调用证据见[验收记录](../quality/MVP-VERIFICATION.md)。

## 数据与凭据

- 默认业务库为项目根目录 `data/agents.sqlite`；可在启动前设置 `AGENT_DB_PATH` 指向另一 SQLite 文件。`data/` 已被 `.gitignore` 排除，尽管本项目当前不用 Git。
- 构建目录默认 `.next`；仅隔离构建时可设置 `AGENT_NEXT_DIST_DIR`，构建与启动须使用相同值。先确认目标目录不会覆盖正在运行的服务产物。
- 原三个角色首次启动时幂等创建。原快捷事项、事实、成果版本、练习及偏好，旧版目标与反馈，以及自定义 Agent 的实例、事项、纠正、偏好、运行和成果均在同一 SQLite；两类事项的可选计划日、截止日与独立排期修订也存在此库。新链路另有追加式 `agent_metric_events` 事件日志，用于固定历史分页与趋势读取范围，不改写旧记录。主题偏好在当前浏览器本地存储。
- 各渠道 Key 仅在后端进程内存中。刷新页面可继续显示连接；停止或重启服务后需分别重新输入。业务库只存渠道名称、地址、模型列表与选择，API 状态不包含 Key。
- 数据库打开时自动迁移旧结构；自定义 Agent 首次建表、补列（包括 `content_revision`、接续来源、两类事项排期与模型选择列）、快捷事项 `source_context_json` 和练习选项 `question_options_json` 补列或创建指标事件日志前，在数据库同目录以 `VACUUM INTO` 生成一致副本。旧快捷事项的来源和旧练习选项默认为空数组，两类旧事项的模型选择默认跟随 Agent，既有成果不变。事件日志的旧记录回填、触发器及补列在事务中完成，后续记录随原业务写入一起提交或回滚。WAL 模式运行时不要直接复制活动数据库文件当作一致备份。旧版启停已使其失效的成果不会在迁移时自动恢复，历史仍可查看。

## 一次性测试数据

- 每轮页面或真实模型测试使用新建的隔离目录和唯一 `AGENT_DB_PATH`，不得把测试事项写入默认 `data/agents.sqlite`。不同端口只有指向同一数据库时才会看到同一日程；隔离端口之间不会同步。日程按计划日展示，只有截止日的事项留在未安排区。
- 验证结束后先停止对应服务，再核对目录仅包含该轮测试产物，清理 SQLite 主文件、WAL/SHM、迁移备份及该轮隔离构建。测试失败时先记录必要的非敏感证据，再完成清理；不得把临时库当作长期业务库。
- `rtk npm test` 使用 `tests/run-tests.mjs` 在独立系统临时目录中运行；测试进程结束后自动清理该目录。原业务库和其他目录不在自动清理范围内。手动隔离测试也须按上一条收尾。

## 停止与恢复

在服务所在终端按 `Ctrl+C`。运行中被进程中断的成果或练习模型任务不会自动重发；重新启动后会显示中断，可手动重试，已保存的输入和已经提交的回答仍在。Key 只在原进程内存，重启后由用户在本机页面重新连接。新版事项迁移及运行恢复先在隔离库或一致备份副本验证，不覆盖运行中的用户库。

迁移失败或需要检查历史备份时，先停止服务，保留现有数据库不动，将选定的 `.backup-*` 文件复制到另一个绝对路径，再用 `AGENT_DB_PATH=/绝对路径/恢复副本.sqlite rtk npm run start` 启动并检查数据。确认副本正确后再决定后续迁移；不要覆盖原数据库或删除 WAL 文件作为常规恢复步骤。备份文件也可能含用户资料，按本机敏感数据保管。

## 运行限制

- 旧版协调员采用确定性规则安排，不进行模型推理；新版分工同样由规则给出，领域成果和旧版练习反馈调用各自 Agent 选定的渠道与模型。
- 旧版短反馈的正文预算 `max_tokens=700`，新版无跨事项来源的成果正文预算为 `2800`、有明确关联来源时为 `4800`；新版流式生成硬超时 120 秒，非流式旧链仍为 60 秒。DeepSeek 流式请求使用 low 思考档，实际请求至少预留 4096 tokens 供思考和 JSON 正文共同使用，正文另受字段长度校验；其他兼容渠道只显示实际返回的思考字段。供应商已收到请求后的取消不保证停止处理或免计费。
- 仅支持本机单用户运行。没有后台定时任务、跨设备同步或公网访问入口。
- 快捷事项不会自行搜索网页、读取招聘站点或核验词表；空资料时模型可生成通用练习，但具体 JD、个人经历、错词和外部来源需要用户提供文本或另行核对。生成时发送本事项参与时间作为建议预算；之后仅调整时间不会改写旧成果中的文字。
