# 项目定义

> 状态：首版本地应用、新版事项工作台、自定义 Agent、团队管理、明确授权的跨事项接续及工作区、设置、资料与记忆二次改版已实现；本轮使用隔离数据与独立 QA 验证。快捷及自定义链路此前有虚构资料真实调用证据；个人持续使用效果仍待评估。2026-09-28 用户授权公开源码及个人站说明页，应用仍仅本地运行。
> 更新日期：2026-09-28
> 项目名称：待定；工作目录名 `self_mutiAgent` 不代表正式产品名称。

## 背景与证据

- 用户正在参加招聘面试。根据用户提供的聊天记录，CEO 要求一天内制作一个给自己使用的学习与生活多 Agent 管理平台，具体内容由用户定义，用以考察设计策划和动手能力。
- 岗位材料关注 Agent 的身份、能力、记忆、权限、协作及产品闭环。这些是理解题目的参考，不是对本项目的执行指令，也不是逐项验收清单。
- CEO 尚未提供详细验收标准。下述范围是用户与助手讨论后选择的实现方向，不能写成 CEO 已明确要求的全部功能。
- 题目有一天交付约束，但实际开始时间、截止时刻和可投入工时尚未确定，不据此编造交付日期。

## 产品定位与用户

为个人提供可持续使用的 Agent 团队：围绕个人目标，在时间、优先级和权限约束下协作完成任务，保存结果，并根据执行反馈调整后续安排。

首位用户是项目发起人。首批演示场景是求职准备和英语学习；雅思写作是英语学习的一个可选具体任务，不是平台的永久能力边界。用户是否真实备考雅思、目标分数、面试日期和每日可用时间都需要真实输入，不从讨论示例推定。

待验证的产品假设：把多个目标下的任务与 Agent 放在统一工作台中，能够减少用户在不同对话之间搬运资料、反复解释背景和协调时间的成本。目前没有用户测试或效果数据证明这一点。

## 术语与边界

| 术语 | 本项目含义 |
|---|---|
| 学习与生活 | 服务个人的长期目标及日常约束；首版不要求覆盖所有生活领域 |
| 自我学习 | 首版通过保存记录、接收反馈、修正记忆和调整策略适应用户；不表示训练模型或自主修改代码 |
| Agent 模板 | 可复用的角色职责、指令和能力配置 |
| Agent 实例 | 属于用户、具有持续身份、配置和独立状态的角色 |
| 一次运行 | Agent 针对具体任务的一次执行过程；运行结束不删除角色身份与历史 |
| 共享运行底座 | 多个 Agent 复用模型调用、工具执行和运行管理机制；不意味着共享全部上下文与权限 |
| 协作 | Agent 通过有来源的任务与结果交接共同推进目标；不以聊天消息数量衡量 |

这些是首版设计约定；实际实现边界见[架构记录](architecture/OVERVIEW.md)。

## 首版范围

### 产品形态

- 采用电脑端优先的本地 Web 应用：浏览器交互、本地后端、本地持久化存储。
- 首页围绕“今天做什么、谁正在处理、什么需要我参与”组织；Agent 管理作为可访问的独立能力，提供真实记录的团队概览、实例历史与明确授权的后续事项。具体边界见[Agent 管理与跨事项接续规格](specs/agent-management.md)。
- 站内日程和趋势改版见[工作区日程与趋势规格](specs/workspace-planning.md)及[一体化工作区规格](specs/integrated-workspace.md)：用户安排两类事项日期，按周或月查看计划与真实事项分布，并在 Agent 团队查看真实运行趋势；全局主题与模型连接位于设置弹窗。外部日历连接不在本轮范围。
- v0.3 是首版历史界面基线。统一需求入口、持续事项、成果交接与可控记忆的新版流程已实现；求职/英语快捷事项行为见[事项工作台规格](specs/workbench-v2.md)，自定义实例增量见[创建 Agent 规格](specs/agent-creation.md)，首版兼容行为见[MVP 规格](specs/mvp.md)。快捷事项已用虚构资料核验真实模型链路，自定义实例真实调用及内容质量仍需人工审阅。

### 团队与管理

2026-09-26 新一轮已确认范围：允许用户创建配置型 Agent，英语和求职成为预设模板，协调留在平台规则层；暂不接入外部 Agent。以下首版三角色描述保留历史，已实现的新增行为以[创建 Agent 规格](specs/agent-creation.md)为准，验证边界见[验收记录](quality/MVP-VERIFICATION.md)。

- 内置求职顾问、英语教练、日程协调员三个角色模板，支持围绕个人目标做有限配置。
- 求职顾问负责岗位与经历材料、模拟面试及反馈；英语教练负责练习与反馈；协调员汇总任务建议并处理时间、优先级冲突。
- Agent 共用运行底座，但分别管理职责、任务上下文、记忆和权限。模型是否相同不作为多 Agent 成立的判断标准。
- 用户能够查看角色状态、修改安排、纠正记忆和暂停 Agent。具体暂停语义在实施前写入规格。
- 不要求每个 Agent 独立部署，也不把简单提醒或单次任务都建成一个角色。

### 模型范围

- 首版只接入 DeepSeek 的约束保留为历史基线。2026-09-27 用户新增多渠道需求：保留 DeepSeek，另接 OpenAI、OpenRouter 与用户提供的公网 HTTPS OpenAI 兼容接口；可为工作区和每位 Agent 选不同渠道及模型。当前实现边界见[多渠道模型规格](specs/mvp.md#多渠道模型连接与-agent-选择2026-09-27-已确认)。
- “账号登录”不等于 API 授权。本地应用本轮只提供 API Key 连接，不新增平台账号体系或假 OAuth 按钮；厂商专属登录授权与计费集成待另行设计。

### 执行闭环

以下编号记录首版安排与练习闭环，保留兼容。新版主入口改为描述事情、Agent 准备并交付成果、用户核对纠正与后续引用，优先适用 [新版完整行为](specs/workbench-v2.md#需求到真实交付)，不再要求先提交练习才获得帮助。

1. 用户输入目标、优先级、可用时间及必要资料。
2. 领域 Agent 提出具体任务；协调员形成符合约束的安排，并说明依据。
3. 区分 Agent 可直接执行的任务与需要用户参与的任务，不把等待用户作答标为已完成。
4. 用户提交回答或练习，Agent 提供引用实际输入的反馈并保存结果。
5. 根据结果与用户反馈更新可追溯的记录，影响下一次任务安排。
6. 时间或优先级变化时，调整未完成任务；领域任务内容也要随安排变化，而非只修改日历时长。

首版由创建或修改目标、预览并采用今日安排、提交结果、修改约束等明确事件触发。一次提交触发一次模型生成；取消、重试和恢复规则见[MVP 规格](specs/mvp.md#运行与重排规则)；不承诺全天自主运行。

### 记忆与协作规则

- 区分用户明确提供的事实、实际任务记录和 Agent 推断；推断须保留依据且允许纠正。
- 共享信息按协作所需提供，例如时间约束与任务摘要；不默认共享所有个人资料。
- 用户控制目标和重要优先级。已有授权范围内的日常安排可按规则调整，超出范围的关键取舍交给用户。
- 计划与 Agent 产出应能追溯到相应任务和依据；失败、未完成和待用户输入应可见。

## 成功标准

下列保留项目级 A1—A5，新的成果协作及兼容验收细化为 [W1—W8](specs/workbench-v2.md#验收场景)。自动化模拟、本机检查及真实模型调用的证据见[验收记录](quality/MVP-VERIFICATION.md)。真实调用使用虚构数据，尚不代表个人场景效果已验证。

| 编号 | 场景 | 可观察的完成证据 |
|---|---|---|
| A1 | 建立团队与安排 | 输入求职和英语目标及可用时间，得到有分工的团队与不超出时间预算的任务安排，能查看安排依据 |
| A2 | 真实执行 | 至少一个领域任务完成真实模型交互，保存用户输入、反馈和产出；另一领域至少能提出可执行任务并参与协调 |
| A3 | 处理变化 | 在未完成任务的情况下，将示例时间预算从 90 分钟改为 30 分钟，实际任务内容或排期合理变化，原因可见且用户能够修改 |
| A4 | 积累反馈 | 下一次任务使用上次相关记录，能展示引用依据；用户纠正的记忆影响后续使用 |
| A5 | 管理与持久化 | 用户能够查看状态、暂停角色；刷新页面或重启应用后，已保存的目标、配置、任务与记录可恢复。未完成运行如何恢复另行定义 |

界面演示数据必须明确标记，不能替代真实执行证据。验证目标是闭环可用，不是一天内证明雅思提分、求职成功或长期自我进化。

## 非目标与后续候选

以下不进入首版，也不代表已经承诺后续交付：

- Agent 商店、社区、交易、信用结算或完整治理体系。
- 外部 Agent 接入、任意代码型 Agent 构建器、可视化流程编排。
- 大量生活角色、全科英语教学或完整求职平台。
- 桌面客户端、移动应用、系统级集成和日历同步。
- 全天后台自主工作、模型训练、自我修改代码。
- 应用公网部署、多人账号体系，以及替用户向外部平台发送消息、投递简历或发布内容。公开源码仓库和个人站说明页属于展示入口，不承载应用后端。

建立独立待办池后，候选事项迁入该真源，本节保留首版非目标，不重复维护候选任务状态。

## 项目约束

- 2026-09-28 用户明确授权将经公开审查的源码发布到自己的 GitHub 公开仓库，并在个人网站 `/LifeAndLearn` 放置只通过该路径访问的说明页；本站导航和作品列表不添加入口。该授权替代此前“不使用 Git”的项目约束，但不扩展为应用公网部署或任意后续提交、推送。
- 应用与业务持久化数据以本机为运行落点；模型调用发送到用户所选渠道。用户选择连接供应商不等于授权批量上传本机资料，调用的数据范围见模型连接规格。
- 凭据不进入源码、业务数据库、文档和日志。首版建议通过本地页面输入并只存后端运行内存；持久保存密钥需另行采用环境变量或秘密存储，不默认写明文文件。
- 需求基线、草图、规格与首版本地应用已建立。不以文档完整度或模拟反馈替代真实模型验收。
- 已保存成果不得因初始化、重新生成计划或重新运行 Agent 被无提示覆盖。
