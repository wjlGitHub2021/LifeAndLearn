## 多渠道模型路由

`src/lib/model-connections.ts` 将 OpenAI、OpenRouter 和自定义 OpenAI 兼容接口的非敏感配置、模型清单、默认选择与逐 Agent 选择存入既有 SQLite `settings`，不新增表。Key 及各连接的验证/在途控制器仅留在后端进程内存；旧 DeepSeek 的内存连接由 `src/lib/deepseek.ts` 保留。`/api/connection` 在同源校验后提供连接、断开、默认与 Agent 选择操作；设置页统一管理渠道，团队概览设置 Agent 覆盖。运行入口按执行角色在 `beginGeneration(agentId)` 选路，每步写入当次模型标识；连接变化会取消该连接的本地在途运行，历史不改写。前端开始按钮按下一步 Agent 的有效模型判断，后端仍独立拒绝断开或失效的选择。

快捷 `work_items` 和自选 `agent_jobs` 增量保存 `model_choice_json` 与独立 `model_revision`，旧记录默认跟随 Agent；补列前沿用一致备份。两类创建 API 和 `model.update` 只接受当前已连接、在清单中的渠道/模型，修改时检查修订与在途运行。`ItemModelPicker.tsx` 在需求框下和已保存详情显示选择及各 Agent 的当前映射。生成和快捷练习按事项明确覆盖、Agent 选择、工作区默认的顺序选路；事务占用运行时再次核对模型修订。断连的固定选择保留但阻止启动，不自动降级；修改选择不使旧成果失效，历史仍记录实际执行模型。

预设渠道地址固定。自定义地址校验公网 HTTPS 基础地址、拒绝私网与本机 IP/域名及跳转，发送 Key 前再解析主机并拒绝私网结果。DNS 校验与实际 fetch 间仍有解析竞态；本机单用户部署下应只填写信任的提供商地址。`/models` 读取成功仅验证模型列表访问；404/405 才允许手动列表后继续。通用调用使用 Chat Completions 与 JSON 输出格式，不兼容的模型会报错并由用户手动重试。历史 DeepSeek 连接与已记录运行不迁移；真实第三方生成尚未验收。

## 新版事项链路

`src/components/WorkbenchV2.tsx` 提供工作台、我的事项、日程与数据、Agent 团队、资料与记忆视图；左侧将前三项归为行动、后两项归为管理，移除了最近事项重复列表。首页跨两类事项选一件待处理焦点，其余待处理事项进紧凑队列；右侧只列尚未出现的后续安排。空库只有一处轻量新建，先输入需求再展开配置。`CompactItemList.tsx` 将两类事项按待我处理、其他进行中与历史显示，提供本地关键词、方式及日期筛选；桌面右侧预览，窄屏点击整行进入原详情，每组客户端分页至多 10 条；状态 API 仍读取全量，尚未改为服务端分页。自定义事项的编辑与详情由 `src/components/AgentWorkspace.tsx` 承载，从统一新建、团队或事项列表进入。两类详情在主区域先显示当前操作，宽桌面右侧放步骤、排期和来源，窄屏通过标题附近的“事项信息”打开。快捷事项的待答题目、选择与理由/自由作答共用顶部唯一入口，成果和练习记录按需切换；长标题可展开全文。原 `/api/work-items` 调用 `src/lib/work-items.ts` 与 `src/lib/workflow.ts`，作为求职/英语快捷事项；其他方向通过下述自定义 Agent 链路执行。原快捷事项的自然语言需求、文本资料、参与时间与优先级继续保留。交互行为见[UX 增量规格](../specs/focus-workspace.md)、[一体化工作区规格](../specs/integrated-workspace.md)和[作答与流式增量](../specs/workbench-v2.md#快捷事项作答与模型流式输出2026-09-27-已确认)。

新版在同一 SQLite 库增量创建 `work_items`、`work_facts`、`work_runs`、`work_artifacts`、`work_preferences`，不映射或改写旧 `goals`、`tasks`、`runs` 与 `memories`。旧版记录通过 `/legacy` 访问。结构初始化复用迁移前的 SQLite `VACUUM INTO` 一致备份机制；事项修订号、事实来源、运行输入快照、成果版本及上游成果 ID/版本均持久保存。角色执行顺序固定为求职顾问再英语教练，创建时规范化，展示时也兼容先前保存的反序记录。偏好由用户主动保存、按角色读取，超过每角色五条有效偏好时明确拒绝。

持续使用闭环增量加入事项 `lifecycle`、成果 `accepted_at`、英文专用要求和按角色内容修订号；另建 `work_practices` 与 `work_practice_runs` 保存题目、真实回答、反馈、下一轮建议、独立运行快照和状态。新选择题的题干仍在 `question`，选项存入 `question_options_json`；旧库在一致备份后增量补列为 `[]`，开放题及旧题继续使用自由文本。旧库新增列与表前保留一致备份，并在事务内复查列结构，避免并发迁移重复加列。事项总修订号用于并发编辑与运行快照，成果按对应角色内容修订号判断有效；时间或优先级变化只更新安排，不使内容成果失效。英文专用修改只影响英语角色；中文变化及上游版本变化会使依赖的英文成果待更新。被移除角色的成果和练习仍作为历史可见。

成果、出题和反馈仍要求模型返回可校验的外层 JSON，正文和题干要求 Markdown；新出题协议把选项单独返回并校验数量，服务端将其结构化保存，不再依赖从长段正文猜测 A/B/C。`generate(onDelta)` 解析供应商 SSE 的 `content` 与实际返回的 `reasoning_content`，`run-stream.ts` 按运行 ID 暂存有界事件并通过 `/api/run-stream` 供当前页面订阅；`RunLivePreview.tsx` 只提取 JSON `content` 字段的增量正文预览，思考字段单独折叠显示，不保存为成果或运行快照。断线、取消、失败与迟到结果仍由原运行状态和最终 JSON 校验决定，预览不能代替已保存成果。流式 DeepSeek 请求启用 low 思考档并使用 120 秒硬超时；因实际思考可能消耗生成预算，请求的 `max_tokens` 至少为 4096，最终正文仍由原字段及长度校验约束。非流式旧版反馈仍维持原超时。其他兼容渠道仅在供应商确实返回思考字段时显示。

快捷事项的跨日来源以 `work_items.source_context_json` 保存显式选定的不可变快照，旧记录迁移后默认 `[]`，补列前用 `VACUUM INTO` 备份。它与同事项求职→英语的 `upstream_artifact_id` 分开：`source.update` 在事务中核对目标修订、来源当前且已确认的成果及循环引用；快捷来源继承既有快照链，并只附带当前成果下最近一次完成练习的题目、作答、反馈与建议。链最多七段、JSON 最多 36000 字符，超限拒绝。更新来源提升两个角色内容修订并将旧成果转入历史，排期修订不变；后续生成和出题输入保存同一来源快照，原运行不改写。参与实例关闭上游权限时阻止启动，已保存历史仍可查看。

工作台首页将两类事项的待核对、受阻、失败和中断状态列为待处理，完成及归档退出列表；核对成果、完成、归档与重新打开均由事务校验当前修订及运行状态。练习在同一快捷事项内分成模型准备题目与用户提交回答后的模型反馈两次独立运行；回答先持久保存，新题只引用同一当前成果且同一预设配置修订下完成的旧轮次，防止已删除资料或收紧权限后旧文本回流。来源成果过期后不能提交旧题，历史轮次仍保留。请求标识核对操作、角色、轮次、修订和答案，重试不会伪装为新作答。进程失去所有者的练习运行与成果运行均转为中断，只有用户手动恢复才再次调用模型。

首页练习待办按当前参与角色及各自当前有效成果，分别读取最近轮次；待答、失败和中断不会被另一角色较新的反馈遮住，主动取消不自动成为首页告警。完成事项时，后端在同一事务核对页面确认的未完练习 ID；有待答、失败、中断或留有题目/回答的取消轮次时，页面要求明确选择继续处理或结束并保留历史。练习按钮按角色启用状态禁用，页面返回前台时重取事项、团队与连接状态；后端继续独立校验。前台保留未保存草稿的编辑基线，若另一页更新事项，则阻止旧草稿直接按新修订保存，要求用户对照最新内容并明确选择；409 后自动刷新。未完轮次或事项修订变化时，旧完成确认面板失效。旧轮次来源失效后，页面按当前成果是否已生成分别提示更新或开始使用新版本。

用户点击“开始协作”才会调用模型。求职与英语联合事项按求职顾问中文成果 → 英语教练英文成果执行，每个角色一次有界生成；英文调用包含实际中文成果的 ID、版本和正文。单角色事项仅调用对应角色。生成输入包含保存的参与分钟数；空资料时提示模型只给通用内容，不声称核验过具体外部来源。本链路不搜索网页或校验模型生成的词汇题答案。生成上限按是否明确关联跨事项来源分别为 `max_tokens=2800/4800`；流式运行使用 120 秒硬超时，Key 仍只在内存，地址由当步 Agent 的渠道选择决定。规则生成的分工不是模型规划。纠正引用要求原文 ID 与来源文本一致，成果片段须出现在正文中，允许空白字符差异；失败保留已成功成果和运行，用户可手动继续未完成步骤，不自动重发。虚构资料真实 DeepSeek 调用已验证第 2 版上游交接、纠正与偏好作用；新增流式交互的真实模型效果仍待本轮隔离调用验证。

保存资料、纠正和启动运行都要求页面提交所见事项修订号，旧标签页的请求以 409 拒绝；偏好编辑与撤销比对原文及原状态，防止旧编辑重新激活已撤销偏好。每次运行以事务校验事项修订、资料/事实/偏好快照、角色启用状态与角色状态代次，再原子占用。结果提交时再次核对当前运行和修订；末步成功与事项就绪在同一事务完成。取消、断连或资料更改后的迟到结果不能覆盖新状态；进程失去所有者的运行标为中断。暂停角色阻止新步骤，即使暂停后迅速恢复，也不会让旧运行自动交接，必须由用户再次继续。调整参与时间更新事项修订和建议，不触发模型请求。

纠正保存为用户原文与来源修订，重新运行形成新成果版本并保留旧版本。求职/英语快捷链路的模型需返回 `content` 和逐条 `appliedCorrections`，服务端检查 ID、用户原文和成果中的连续引用片段；自定义 Agent 链路的协议见下节。这验证引用结构与可追溯性，不能证明语义判断正确，仍需用户核对。新版事项事实只进入所属事项；有效角色偏好可以进入后续相关事项的输入快照，撤销后不再进入新调用。

## 自定义 Agent 增量链路

正文呈现偏好与 JSON 输出协议在系统提示中分开：当前实例有效偏好仍作为结构化用户输入，允许指导 `content` 的标题、分节、条目数量和顺序；不得更改职责、交付物、事实、权限和引用协议。提示要求返回前自检并合并表达以保留相关事实，没有新增自然语言约束解析器、结果截断或额外模型调用。正文格式是否遵从仍由模型决定，服务端未增加确定性条数校验。

自定义链路的 `agent-workflow.ts` 使用 `{content, appliedCorrections:[{id,excerpt}]}`，不要求模型复述纠正原文。服务端核对授权来源 ID、覆盖数量、重复来源、摘录长度、可见内容及其在存储正文中的连续出现；若响应仍带旧 `sourceText`，必须与来源原文一致。纯默认可忽略字符、盲文空白等不能冒充证据。错误只记录不含原文的诊断分支，不持久保存供应商原始响应，不自动重试；这些校验仍不能证明语义正确。提示明确总体目标与本步职责/交付物，允许本步要求的上游全文翻译或润色，不额外代做其他步骤；未扩展原始运行快照、权限或成果有效性哈希。

`MemoryWorkspace.tsx` 从已加载的快捷事项、自定义事项和 Agent 状态构造本地资料索引，分别展示有正文的事项资料、快捷/自定义明确纠正、当前可接续的已确认成果和 Agent 偏好；没有新资料表、索引服务或模型调用。各类别按标题、正文或 Agent 名称做客户端关键词匹配并展示片段。详情按参与实例当前 `allow_material` / `allow_upstream` 展示权限，同时说明新事项仍需重新检查；旧版运行输入快照不受编辑影响。快捷纠正没有单条停用字段，只标记为“已记录”；自定义纠正读取真实有效/停用状态。偏好显示有效及已撤销历史，保存、编辑、撤销复用现有 API 与陈旧编辑基线；资料和纠正修改仍回所属事项，已确认成果接续仍须在后续事项显式选择。事项详情对暂停步骤提供恢复入口，恢复仍需手动继续；历史成果可展开查看，运行结束后清除过时的启动提示。

`src/components/AgentWorkspace.tsx` 承担团队创建/编辑/启停、权限与偏好，以及「Agent 事项」的步骤、交接、运行、纠正、成果和历史。`/api/agent-work` 使用已有的同源与请求体保护，再调用 `src/lib/agent-work.ts`、`src/lib/agent-workflow.ts`。新链路可选预设求职/英语或任意自建实例；旧快捷事项、练习和 `/legacy` 没有迁入新表。页面的首页待办、最近事项和“我的事项”汇总两类事项，详情按原数据链路打开。自定义事项的完整成果历史不依赖当前步骤列表，删除或重排步骤后仍能按生成时来源查看。

同一 SQLite 库增量创建 `agent_profiles`、`agent_jobs`、`agent_corrections`、`agent_preferences`、`agent_runs`、`agent_artifacts`；首次建表或补列前以 `VACUUM INTO` 保存一致副本。实例使用稳定 UUID（预设保留既有 ID）、启停状态与配置修订；预设启停同步旧角色。自建实例另有 `content_revision`：职责、交付物和资料权限改变时与总修订一起递增；仅启停时只递增总修订，继续拒绝陈旧编辑和运行提交，但不使已有开放事项成果失效。旧库增量补列前先备份，并用原总修订回填，使迁移时仍有效的成果哈希保持一致；已经因旧版启停失效的成果不自动恢复。每个实例最多五条有效偏好。事项最多四个有序步骤，用户逐步选择 Agent 和明确上游成果，步骤只接受较早步骤的引用。每步一次模型调用，不自动收费重试。运行前页面展示 Agent 职责、交付物、资料与上游范围以及预计调用次数。

每次运行只组装该实例获准的事项资料、有效纠正和偏好、选中的当前上游成果。预设实例的快捷成果和练习也读取同一配置与有效偏好；旧 `work_preferences` 与新 `agent_preferences` 通过统一读取入口可见、可撤销，不迁移或删除原行。预设配置变更使开放快捷事项的旧成果失效；无配置快照的旧成果仅在默认权限和初始修订下继续视为当前，权限收紧后必须重生。旧 `/api/run` 在预设禁止资料时拒绝启动，因为旧任务提示不能安全拆分资料。自建实例的成果输入哈希使用内容修订，预设实例仍使用总修订与旧角色代次；运行占用和提交继续核对总修订及启停状态，故暂停期间的新步骤与迟到结果不能提交。输入哈希还包含相关事项内容及上游成果 ID/版本。运行和成果保存输入及配置快照；完成事项保留已确认成果，即使 Agent 后续改名；归档仅展示历史。纠正上限为十二条有效记录且总文本不超过八千字符，停用旧纠正保留历史并释放容量。资料、内容配置、纠正、步骤或来源变化会令相关当前成果失效，旧版本仍可查。

运行由 SQLite 事务占用并以请求标识去重；结果提交再次校验修订和输入，取消或迟到响应不能提交。顺序交接时再次比较整条链的实例修订与启停状态，变化后等待用户手动继续；主动取消与配置变更触发的取消在首页待办中区别处理。失主运行在重启后标为中断，手动重试产生新运行。新链路复用已有 DeepSeek 内存连接与固定地址；流式生成硬超时 120 秒，无跨事项来源时 `max_tokens=2800`，明确关联来源时 `max_tokens=4800`，`finish_reason=length` 作为可诊断失败。模型 JSON 中的纠正引用由服务端核对。隔离 mock 已验证版本与资料来源，本机原连接下的虚构短文单 Agent、交接和纠正重试成功；具体边界见[验收记录](../quality/MVP-VERIFICATION.md#nr1nr4-修复与定点验收2026-09-26)。

## Agent 管理与跨事项接续

`/api/agent-metrics` 通过 `agent-work.ts` 的既有状态计算 Agent 事项指标；`agent-metrics.ts` 区分运行启动、成功、失败和成果确认。团队只返回 7 日计数及轻量实例概览，点开指标再按页取对应事件；单 Agent 详情分别按页取参与事项和历史事件。`agent_metric_events` 以触发器记录实例、事项、运行、成果及确认的单调事件序号；读事务取得一致的业务行与高水位。续页带首次读取时间、序号高水位与时间/ID 游标，固定同秒新写入前的成员和总数。旧库回填与建触发器在一致备份后的事务内完成。错误仅输出分类摘要，详情的历史职责和来源取运行/成果快照。工作台仍汇总快捷与 Agent 事项，但团队指标只统计 Agent 事项；不计算未采集的 Token、费用或自动质量分。

跨事项接续由用户在一份已确认成果上明确发起，`agent_jobs` 持久保存来源事项、成果 ID/版本和可选标签，步骤中的 `source` 标记决定哪位 Agent 能接收该成果。`job.continue` 与 `job.continuation.update` 在事务内核对确认状态、固定版本、目标修订、步骤权限与来源有效性；`inputFor` 只把选定成果加入获准步骤的上游输入与哈希，不带入来源事项其他资料。旧库补列前用 `VACUUM INTO` 保存一致备份。来源更新或归档不改写目标的固定版本；取消接续不改写既有运行快照。规则和已验证边界见[增量规格](../specs/agent-management.md)及[验收记录](../quality/MVP-VERIFICATION.md#agent-管理与跨事项接续隔离验收2026-09-27)。

## 工作区日程、设置与趋势

`WorkbenchV2.tsx` 的右侧顶栏随正文吸顶，桌面侧栏与正文各自滚动；正文滚动容器禁用边界回弹。`WorkspaceSettings.tsx` 将设置分为使用偏好、外观、模型连接、数据与隐私、使用说明；默认打开页面与日程周/月视图保存在当前浏览器 `localStorage`，主题仍用原偏好，Key 仍只在后端内存。数据页只展示真实库计数与管理入口。`IntegratedSchedule.tsx` 在「日程与数据」中合并两类事项的周/月日历、所选日/未安排/逾期清单与原排期编辑器；只按 `planned_date` 入日历，只有截止日的开放事项留在未安排区。顶部显示注明口径的周期计划、全部开放未安排和截止逾期数；环图与柱图退到可展开的数据区，仍分别按全部开放事项的排期占比和所选周/月每日未归档计划件数统计，只从当前本地事项生成，不调用指标 API。团队的真实运行趋势仍使用独立的滚动 7/30 个 24 小时窗口，不与日历周期混算。截止逾期只作提示。

`work_items` 与 `agent_jobs` 增加 `planned_date`、`due_date` 和独立 `schedule_revision`，旧记录日期为空。两条 API 的 `schedule.update` 同时提交计划日和截止日，按排期修订拒绝陈旧写入；它不改变内容修订、运行输入或已有成果。新增列前仍使用 SQLite `VACUUM INTO` 一致备份，并在事务内迁移。页面跨详情、周卡与导航暂存未保存的排期草稿，冲突时由用户核对最新状态。

`/api/agent-metrics?trendDays=7|30` 复用追加式 `agent_metric_events` 的高水位与固定时间，给出连续 24 小时桶及四类事件总数；选桶后按同一 `asOf` 和事件序号有界游标分页。团队页用可键盘操作的 SVG 折线显示真实运行启动、成功、失败及成果确认，不混入快捷事项，不将次数解释为学习效果。口径、交互和隔离证据见[PI 规格](../specs/workspace-planning.md)与[验收记录](../quality/MVP-VERIFICATION.md#工作区日程与趋势增量验收2026-09-27)。

## 系统边界

本地单用户 Web 应用，页面和业务数据在本机，模型执行通过用户选择的模型渠道。新版行为以[事项工作台规格](../specs/workbench-v2.md)为准，旧版兼容行为以 [MVP 规格](../specs/mvp.md) 为准；本文件定义实际实现边界。公开源码和个人站说明页不改变应用未公网部署的运行边界。

## 已实现组件

| 组件 | 实现 | 职责与边界 |
|---|---|---|
| Web 页面 | Next.js、React、TypeScript | 新版事项工作台与 `/legacy` 旧版目标/练习；共享主题和模型连接 |
| 本地后端 | Next.js Route Handlers，Node.js 运行环境 | 输入校验、凭据管理、业务流程与模型代理；仅监听回环地址 |
| 业务存储 | SQLite | 新版事项、事实、运行、成果、偏好及旧版目标/练习记录；不存 API Key |
| DeepSeek 适配器 | 内置 `fetch` 轻量适配 | 固定官方地址，处理模型列表、Chat Completions、超时、取消、迟到响应及安全错误映射；不增加生成 SDK |
| 旧版练习底座 | `src/lib/store.ts`、`feedback.ts` 和 `/api/run` | 保留目标、任务、反馈和旧版协调；新版复用角色状态与连接适配器 |

前端不得直接访问 SQLite 或持有后端使用的长期凭据。页面、业务服务与供应商适配分层，避免在路由或组件里散落模型调用。首版按用户事件启动短任务，不依赖定时调度或独立队列服务。

## DeepSeek 接口依据

2026-09-26 核实官方文档；以下是接口文档事实，实际调用证据单独见[验收记录](../quality/MVP-VERIFICATION.md)：

- [首次调用 API](https://api-docs.deepseek.com/zh-cn/) 给出的兼容接口根地址为 `https://api.deepseek.com`，请求使用 Bearer API Key，生成接口为 `/chat/completions`；当前列出 `deepseek-flash` 和 `deepseek-v4-pro`。
- [模型列表](https://api-docs.deepseek.com/api/list-models/) 定义 `GET /models`，返回请求标识 `id` 与展示名 `name` 等元数据。当前 `deepseek-flash` 的展示名是 DeepSeek-V4.1-Flash；`deepseek-v4.1-flash` 不是文档列出的请求标识。应用只接受实际返回与支持范围的交集，并显示展示名及请求标识。
- [Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/) 与 [JSON Output](https://api-docs.deepseek.com/guides/json_mode/) 支持关闭默认思考模式并要求 JSON 对象输出；短反馈任务使用 `thinking: { type: "disabled" }` 和 `response_format: { type: "json_object" }`，生成后仍校验字段及引用证据。
- [错误码](https://api-docs.deepseek.com/quick_start/error_codes/) 区分鉴权失败 401、余额不足 402、限流 429、服务端错误 500/503；应用映射安全的提示，不直接转发原始错误对象。

仅连接固定官方 HTTPS 地址，不允许任意 Base URL 或把含鉴权请求重定向到其他主机。API Key 使用范围及生命周期以 [连接规格](../specs/mvp.md#deepseek-模型连接) 为唯一真源。

## 关键流程

连接：本地表单 → 同源后端校验 → 官方模型列表 → 验证成功后原子替换内存凭据与连接版本 → 前端只接收状态和模型信息。

执行：用户发起领域任务 → SQLite 事务原子占用任务并保存输入和运行标识 → 加载该目标及角色在当前练习方式下兼容的记忆、偏好 → 从本次回答生成最长 103 个 Unicode 字符的连续原文候选片段及编号 → DeepSeek 单次生成并选择引用编号 → 服务端验证编号且用原片段组成反馈 → 保存结果并更新任务。模型若沿用旧 `evidence` 字段，仍须满足 4—120 字符的原文连续匹配；同时提供两个引用字段时必须一致。校验按 JSON、证据、反馈与建议区分安全原因并存入失败运行，不保存模型原始响应，也不自动重试。当前没有通用工具执行器；手动重试保留原运行证据。

英语角色在单次生成提示中增加语法校核：先核对完整谓语和题目要求，再区分真实语法错误与可选风格建议；求职角色不使用这组英语指令。未增加第二次模型调用或规则替换反馈正文，输出协议和历史记录保留方式不变。

协作：领域角色按目标、训练偏好、同目标记忆和上次反馈建议生成规则任务 → 协调员规则按时间预算、优先级或均衡偏好分配 → 用户预览并采用 → 对应角色执行。上次任务建议只有在其来源运行未被该目标和角色采用或纠正时才能按“尚未采用”回退；来源记忆即使被当前方向过滤，原建议也不再回流。冲突的口语或写作要求不进入新任务及后续反馈；明确拒绝文字转写的纯语音目标在预览中标为不支持。安排依据保存在任务中；当前协调员不发起模型请求。

口语/写作方向由同一局部词句规则提供给任务题型、纯语音检查及记忆/偏好筛选。记忆的 `effective_order` 在采用或纠正时于 SQLite 即时事务中递增；读取先按有序操作的新记录排序，旧记录沿用 `created_at` 和 `rowid`，再过滤冲突内容并限制五条。预览和模型调用都通过同一读取入口取得记忆；提案校验纳入操作序号，纠正后旧预览失效。

## 数据与运行状态

- SQLite 是业务数据的权威来源，页面只显示已保存状态或明确标出的未保存草稿。
- 模型选择与每次运行使用的模型分别记录；更换默认值不改写历史。
- 连接使用递增版本隔离替换、断开与迟到响应；请求结束时释放计时器及取消监听。
- 初始化角色应幂等。运行建立去重标识；默认不自动重发可能已被供应商执行的生成请求。
- 同一任务的运行建立先条件占用任务再插入运行记录，两步在 SQLite 事务内；并发的其他进程不能为该任务再建立第二次运行。取消或断连会立即结束本地等待，即使供应商忽略取消信号。
- 后端重启或状态读取时，失去原进程的未完成运行标记为中断，允许手动重试。
- 数据库采用 WAL；已有结构迁移前通过 SQLite `VACUUM INTO` 生成带时间戳的备份，并在事务中迁移。备份恢复需停止应用，见[运行手册](../operations/RUNBOOK.md)。
- 旧库首次访问会补齐记忆排序列，不改写旧记忆正文、创建时间和运行引用；开发进程复用已有连接时也会检查这一结构版本。并发迁移仍先备份，再在事务内按当前列状态补齐。

## 风险与保护

- 本地 API 仍需校验 Host、Origin 和请求格式，设置同源会话/请求校验，防止外部网页借用本地凭据；不启用通配 CORS。
- 模型连接、替换、断开和调用接口不得记录秘密请求体；错误仅保留经过筛选的状态码及运行标识。
- Key 验证使用有界超时，页面离开、替换和断开处理取消。供应商不可用时保存失败状态，保留本地资料，不伪造结果。
- 旧版短反馈生成上限 `max_tokens=700`，新版成果为 `2800`；连接验证硬超时 10 秒，生成硬超时 60 秒；不宣称精确控制供应商最终账单。
- 依赖已锁定在 `package-lock.json`，Node.js 22.22.3 上完成本机检查。虚构数据的真实接口调用已通过；个人资料下的反馈质量仍待实际试用。
