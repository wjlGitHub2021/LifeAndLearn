当前候选唯一可编辑源：[workbench-v2.html](workbench-v2.html)。下方 v0.3 记录和旧源保留为历史基线，不继续并行维护两套当前设计。调研依据见 [UI 参考记录](UI-REFERENCES.md#事项工作台重设计调研)。

### 设计选择

- 统一入口先描述要完成的事情；首页汇总需要用户参与的环节及最新成果。
- 持续事项保存资料、分工、成果及纠正上下文。导航改为工作台、我的事项、Agent 团队、资料与记忆；事项详情仍保留导航。
- Agent 先交付可用草稿，用户核对后再练习。示例交接为求职顾问的中文提纲供英语教练生成英文介绍，协调员汇总。
- 成果保留版本；事实纠正同步到相关成果。事项事实和用户主动保存的长期偏好分开，偏好可撤销。
- 团队展示职责及可用资料，暂停会阻止后续协作和更新。固定明暗与独立主题色继续互斥，分别记住选择。
- 用户的 45 分钟指核对和练习时间，不包含 Agent 准备工作。草图不实现真实计时或后台调度。

### 推荐体验路径

1. 工作台保留预填示例，点击“一起推进”，查看角色分工与资料范围。
2. 点击“开始协作”，打开中文提纲和英文介绍，查看交接来源。
3. 点击“填入示例纠正”与“更新相关成果”，确认两份成果从 v1 更新至 v2；切换原版本进行对照。
4. 可选择保存英文表达偏好，在“资料与记忆”查看并撤销；项目角色纠正仍保留在事项内。
5. 在团队页暂停英语教练，再返回事项，更新按钮应不可用；恢复后可继续。

### 模拟边界

- 只有一个虚构面试事项，不代表平台只能服务面试；本轮尚未验证其他学习和生活场景的适配性。
- 生成、交接、纠正均为点击驱动的固定示例，没有模型、工具、文件上传或后台运行。非预设输入会明确提示，不能伪装成已完成任意请求。
- v1 故意预设“参与”被扩大为“主导”的缺陷，并在成果中明确标记，仅用于演示纠正链路；正式模型应尊重来源事实。
- 页面、阶段、纠正、主题、暂停状态和预设偏好可由宿主恢复；自由输入不持久化。不把宿主恢复等同于正式应用的数据库和进程重启验收。
- 后续练习、更多事项创建、角色配置及新 Agent 构建不在草图可点击范围内。正式应用应实现哪些能力以新版规格为准，草图限制不直接变成产品限制。

## 草图设计与基线确认

2026-09-26，用户明确表示页面先保持当前状态，未来有新需求再逐步优化。以下为本次接受的草图设计说明；正式行为见规格，运行细节仍需收敛：

1. 一级导航为今天、目标、Agent 团队和执行记录；任务详情属于下级页面，保留全局侧栏。
2. 首页以任务为中心；团队状态位于右侧，窄屏移到下方。使用列表与分隔线降低重复卡片的视觉重量。
3. 改变可用时间后先展示调整建议；用户采用后才修改当前安排。此处用于展示控制权，不表示未来每次日常调整都必须确认。
4. 任务详情把练习工作区与任务来源并排，展示目标、领域 Agent 建议、协调员安排三个环节。
5. 示例反馈就绪不等于任务完成；用户查看后结束练习，首页和执行记录随之更新。
6. 下次训练建议单独供用户采用；它只是可追溯的建议，不自动升级为能力标签。

可选设计对照包括协作依据位置、列表密度。控件由支持该功能的预览宿主提供，缺失时默认布局仍可使用。旧的宿主外观对照已移除，主题只通过页面顶部控件切换。

## 推荐走查路径

1. 在“今天”查看两个示例目标、任务时长和角色分工。
2. 将时间从 90 分钟选择为 30 分钟，点击“查看调整”；观察原安排此时仍保留。
3. 先尝试“保留原安排”，再重新查看并采用建议；确认求职与英语的任务内容和时长同步缩小。
4. 进入任一任务，查看来源说明，输入回答或填入示例。
5. 点击“提交并预览反馈”；可选勾选模拟失败，再重试，确认回答保留。
6. 查看标注为预设内容的示例反馈，采用下次建议并结束练习，返回首页检查状态。
7. 点击侧栏的目标、Agent 团队与执行记录，查看关联任务、职责范围及当前会话结果。
8. 顶部选择浅色，再切到主题色并选择暖棕；确认明暗选项收起，切回明暗主题恢复浅色。输入草稿后切换主题，确认回答仍在。

示例中的“明天有面试”、时间预算和作答内容均为虚构场景材料，不代表用户真实资料。反馈为固定示例，不对任意输入评分。
