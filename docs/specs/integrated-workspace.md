# 一体化个人工作区体验增量

> 状态：2026-09-27 用户已确认要重构「我的事项」、左侧导航、开始路径及日期与数据展示；以下具体分组、图表口径和交互是依据现有数据与调研形成的实施方案，个人使用效果尚未验证。
> 范围：仅调整新版页面的信息架构与呈现，不改变事项、排期、Agent 运行、权限、成果和记忆的持久语义。旧规则见[事项规格](workbench-v2.md)、[排期与趋势规格](workspace-planning.md)和[聚焦式工作区规格](focus-workspace.md)。

## 用户问题与目标

当前「我的事项」把所有进行中与历史事项无界平铺；侧栏最近事项、首页焦点与右侧摘要重复展示同一事项；日期只有独立的「本周」页，周日的计划可能排在六张空日期卡之后。用户因此难以判断先做什么，也难以把学习与生活事项、Agent 协作、日期和数据放在一起理解。

目标是让首屏回答「现在做什么、如何开始」，事项页回答「哪些需要我处理、如何找到旧事项」，日程与数据页回答「哪天安排了什么、安排覆盖如何」。页面不把 Agent 运行次数、成果确认次数伪装为学习效果。

## 页面结构

1. 左侧主导航收敛为「工作台」「我的事项」「日程与数据」；「Agent 团队」「资料与记忆」作为管理入口。侧栏只保留一个新建入口，移除重复的最近事项列表。旧版记录仍可从相关页面进入。
2. 工作台保留一件最需要处理的事项与简短队列；空状态用清楚的路径说明：写下学习或生活目标、选择参与 Agent、保存后手动运行、核对或纠正成果。新建入口展开同一草稿，不让用户在多个创建流程中重输需求。当前事项不在侧栏和首页摘要中重复占多张卡。
   没有待处理事项时，焦点先取计划日或截止日最早的开放事项，并显示日期；有同日安排时在紧凑队列提示，而不是按最近编辑时间跳到更晚的一天。
3. 「我的事项」默认展示待我处理，另可切到其余进行中与历史。三组分别计数；紧凑行显示状态、下一步、计划/截止日，操作文字与状态一致。每页最多 12 条，可翻页找回任意历史；创建和旧版记录入口仍可达。列表分页只控制呈现，现有状态 API 仍全量加载，未来大库性能另行评估。
4. 「日程与数据」在同一页面提供周/月切换、上一/下一周期、回到今天、选中日期及该日事项；周一为首日，月视图覆盖整月。只按 `planned_date` 放入某日；`due_date` 仅作提示。开放且无计划日的事项有明确入口，不因只填截止日被当作已安排。
5. 环形图只展示全部开放事项中的「有计划日／未安排」构成，两个类别互斥且合计等于开放事项总数；中心、图例和百分比都给出文字。日期柱图按所选周/月逐日统计计划事项件数，含完成但不含归档；图旁或选中日期列表提供等价数值。零数据不画虚构扇区或柱。两图使用当前本地真实事项，不作为效率或学习成效评分。
6. Agent 团队现有 7/30 个滚动 24 小时事件趋势继续明确标注「仅 Agent 事项」；它与按本地日历周/月的计划图口径不同，不混算成同一饼图或同一周期合计。

## 验收场景

| 编号 | 可观察结果 |
|---|---|
| IW1 | 首页空数据时能直接理解从需求到 Agent、成果和纠正的路径；有待办时一屏可找到首要动作；侧栏没有与主区重复的最近事项。 |
| IW2 | 「我的事项」的三组计数准确；待我处理与其他进行中、历史互不重复；超过 12 条可翻页找到最后一条，切组后页码重置。 |
| IW3 | 日程可切周/月、前后周期并回到今天；周日事项不被六张空卡压出首屏，选日只显示该日计划，未安排及只填截止日仍可达。 |
| IW4 | 环图两段数量加总等于开放事项数；柱图逐日数量与日程卡一致；空库、无计划日、仅截止日、已完成及归档均按定义展示。 |
| IW5 | 两类事项从列表和日期都能打开原详情，原排期编辑、草稿、成果、练习、历史、Agent 运行和权限链路不受影响；没有新增自动模型调用。 |
| IW6 | 桌面与 390px 无横向溢出；日期、分组、翻页及图表文字信息可键盘获取，图形不依赖颜色或悬停传达唯一信息。 |

## 设计与验证边界

GOV.UK 的多任务入口、Carbon 的部分与整体图表、USWDS 和 W3C 的图表可访问性指引用于形成具体交互；来源与取舍记录在[UI 参考](../design/UI-REFERENCES.md)。这些是设计推导，不是本产品的用户测试结论。使用隔离数据与页面检查空库、混合事项、长列表、周/月边界和窄屏，不触碰用户业务数据或真实模型连接。

## 工作区二次重构（2026-09-27 已确认）

用户要求将工作台、我的事项、日程与数据及设置一起重构。前三项继续是「行动」入口，Agent 团队和资料与记忆继续是「管理」入口；当前没有足以支撑独立“学习成效”页的真实成效数据，故不增加一个只有排期件数的顶层复盘页。设置行为以[日程与设置规格](workspace-planning.md#页面结构与设置)为真源。

1. 工作台有事项时以最早需要用户处理的一件事为主，其他待处理事项组成紧凑队列；没有待处理事项时取计划日或截止日最早的开放事项。右侧只显示未在主焦点/队列出现的后续安排和运行提示。空库时直接呈现一次轻量新建，不再同时出现两个“开始一件事”入口；新建先写需求，再展开角色、资料与日期。没有选择预设角色的已保存事项仍需用户决定分工，应列入待处理。
2. 我的事项保留两类事项的一处入口，默认待我处理；关键词可检索标题、状态与下一步，并可按预设/自选 Agent、计划日有无及截止逾期筛选。各组计数随筛选变化；桌面选择列表行后在右侧看下一步、状态和日期，再明确进入原详情。窄屏直接在行内打开。切页后回到列表保留本次会话的分组、筛选和选中项；空结果提供清除筛选。
3. 日程先帮助安排：周视图使七天在首屏可选，月视图保留概览；所选日期、未安排和截止逾期事项在右侧常驻清单切换，移动端在日期区下方。改期复用原排期编辑器和并发校验，不增加自动安排。顶部摘要分别注明所选周期未归档计划件数、全部进行中未安排件数、截止逾期件数，时间范围不可混淆。原排期图与每日件数图放在明确的次级数据区，保留事项下钻和文字数值；不展示没有采集依据的学习成效、实际用时或完成趋势。
4. 设置扩展为使用偏好、外观、模型连接、数据与隐私、使用说明五类。默认打开页面和日程默认周/月视图是当前浏览器本地偏好，必须实际影响下一次打开；主题、DeepSeek 内存 Key 和手动运行边界不变。数据页只展示当前库真实计数和管理去向，不展示尚未实现的导入、导出或清除按钮；Agent 职责和权限继续在团队页管理。

| 编号 | 可观察结果 |
|---|---|
| WS1 | 空库首屏只有一处轻量新建；混合事项首屏有明确焦点与紧凑待处理队列，右侧不重复同一事项。状态、计划日和截止日与原记录一致。 |
| WS2 | 两类事项可按关键词、方式和日期筛选；桌面预览与原详情跳转正确，移动端可直接打开；返回列表保留选择和筛选。 |
| WS3 | 周/月切换、七天选择、所选日/未安排/逾期清单与改期可用；计划日和截止日语义清楚，统计仍可查看和下钻；1280×720 与 390px 无全页横向溢出或必须下翻才可选择本周末的布局。 |
| WS4 | 设置五类内容与真实计数可读；默认页面/日程视图刷新后生效，主题和模型连接不回退；弹窗可用 Escape、Tab 操作并把焦点送回触发处。 |
