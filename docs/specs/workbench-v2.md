# 事项工作台行为规格

> 状态：Implemented；原 W1—W8、持续使用改进、CD1 快捷事项跨日接续与 Markdown 正文/流程图均已实现并完成隔离验证；个人真实效果仍需评估。
> 设计依据：[已认可草图说明](../design/WIREFRAME.md)、[草图源](../design/workbench-v2.html)。

## Markdown 正文与流程图（2026-09-27 已确认）

成果、历史版本、跨事项来源、练习题、作答、反馈、资料、纠正、偏好及 Agent 长文本以原始字符串保存，阅读时统一支持 Markdown 与常用 GFM 表格、任务列表。编辑区仍输入原文，非空草稿可展开预览；复制成果取得原文。已有纯文本及换行继续可读，不进行数据库迁移，也不因预览触发模型调用。事项标题、导航、按钮和状态标签保持简短纯文本。

正文中的 `mermaid` 围栏代码块绘制流程图。图表进入可见区域后再加载；始终可展开源码，语法错误、超长或绘制失败时显示源码与明确提示。图表是内容表达，既有事项步骤和 Agent 权限规则不因图形改变。正文不执行原始 HTML，不启用不安全链接；远程图片只显示替代文字，避免阅读模型内容时自动向外部地址请求。Mermaid 使用严格安全模式与有界大小，SVG 作为隔离图片呈现；表格、代码和图表在内容区内处理宽度，窄屏不得撑宽整页。

验收：快捷事项、自定义 Agent 事项及旧版练习的主要正文与编辑预览均能显示标题、列表、表格和流程图；旧纯文本可读且原文可复制。无效流程图保留源码且没有残留错误图层；HTML、危险链接和远程图片不执行或自动加载。桌面与 390px 页面无横向溢出，原有事项、运行、权限和历史功能回归通过。

### 快捷事项作答与模型流式输出（2026-09-27 已确认）

用户在真实事项页发现当前题目和回答位置分散，历史练习重复展示待答题、原始运行输入横向溢出，模型生成阶段又只有完成后的结果。此增量以[官方交互与协议调研](../design/UI-REFERENCES.md#事项作答与实时模型输出调研2026-09-27)为参考。

- 快捷事项主区先显示唯一的当前题目、作答和提交入口；成果与练习记录作为可切换区域，运行快照只在按需展开时显示。长事项标题可收起并显式展开全文；桌面与窄屏均使当前操作在一至两个视口内可达。旧轮次仍可追溯，不把待答题重复放进历史操作区。
- 模型交付的成果、练习题、反馈和下轮建议使用 Markdown 正文；JSON 只作为传输与校验外层。新选择题将题干与 2–6 个选项分开存储，页面提供原生单选及独立理由输入，提交后保存为本轮实际作答。开放题与旧题继续用自由文本；清晰标为 A/B/C/D 的历史题仍用自由输入。阅读层可将连续完整的 A/B/C/D 文本排成列表，不猜测可点击选项或正确答案，也不改历史原文。
- 快捷成果、练习准备/反馈及自定义 Agent 成果在模型运行时接收 SSE 增量。客户端只从 JSON 外层目标字段读取可见 Markdown 草稿，标明“实时草稿”；校验成功后才写正式内容。DeepSeek 流式请求使用低强度思考模式，若渠道实际返回思考字段则与正文分开展示；其他渠道或未返回时不伪造思考链。思考仅为本机短时预览，不作为事实依据或长期记录。
- 取消、断连、格式错误、超时与迟到结果继续服从原运行修订和权限校验，失败时不保存部分正文。实时流只保留短期有界内存事件；刷新或进程重启不重发模型请求，历史以持久运行和成果为准。

验收需覆盖：桌面与 390px 的当前题、作答和提交；选择题和开放题各一次；Markdown 标题/列表和长 JSON 快照不撑宽页面；可见增量与实际渠道思考字段；作答反馈就地可见；失败、取消和重连不把草稿当正式成果。模拟供应商只能证明协议与界面，真实内容质量需要独立真实模型调用和人工核对。

## 页面与入口

- 保留左侧导航：工作台、我的事项、Agent 团队、资料与记忆。模型连接和主题位于全局区域，任何详情不丢失主导航。
- 桌面宽度大于 600px 时，工作台占满视口，右侧内容独立纵向滚动，滚动到顶部或底部不回弹，左侧导航不随右侧移动；矮窗口下侧栏可独立滚动以保持底部入口可达。窄屏保留纵向排列和整页滚动。切换页面或打开不同事项时回到顶部，同页数据刷新、编辑及主题切换不重置阅读位置。
- 工作台用自然语言需求作为主要入口，汇总真实的待参与环节和最新成果，不显示虚构进度或成绩。不要求先填写一套目标表单、安排练习再获得帮助。
- 我的事项支持新建、查看和继续已有事项；事项保存原始需求、用户补充材料、分工、运行进展、成果及纠正。刷新和重启后可继续。
- 事项工作区以成果和用户需要做的事为中心；协作依据与来源可展开查看，不用 Agent 互相聊天消息堆叠充当成果。
- 保留明暗与独立主题色互斥规则，两套选择分别持久化。新用户默认浅色，已有用户保存的主题优先，不重置现有偏好。
- 输入框、导航和成果在窄屏重排，用户未提交内容在同页切换主题及站内切页时保留；刷新仅保证恢复明确已保存内容，离开时避免无提示丢失。

## 需求到真实交付

1. 用户输入需求；本事项文本资料可留空，时间与优先级可调整。空资料仍能开始通用框架和练习；缺少关键信息时明确列出所缺内容，不能编造经历、岗位或能力事实，也不能声称未核验的外部词表分组、词频或实时岗位信息来自可靠来源。示例是用户主动选用的独立虚构资料。
2. 保存事项，展示计划：参与角色、各自交付物、先后依赖、资料范围、需要用户参与的环节。按需求选择角色，不强制每件事三位都运行。超出两领域能力时说明限制，不把无关需求套成面试流程。
3. 用户点击开始协作后，执行有界的真实模型调用链。协作计划若也调用模型，应明确显示生成状态、失败与该次运行；协调员可采用透明规则，不能伪装成模型自主推理。
4. 求职与英语联合事项中，求职顾问先基于用户材料生成中文内容；英语教练读取该成果的明确版本进行英文表达。每次运行持久记录角色、输入来源、模型、状态及输出，不能由单一固定输出冒充多个角色运行。
5. 成果带负责角色、来源、生成版本和状态。用户可查看、复制并继续提出修改；没有资料支持的细节标为待核对，不能预设“主导”等虚假经历。
6. 用户提供的新指令应影响本次结果，不能只识别草图中的固定纠正。空输入、超长输入及无关指令须有明确反馈。可以请求澄清，不能在失败时以演示内容兜底。

每个运行步骤限制请求次数、输出和超时，不自动无限重试或循环自我改进。一次协作可能包含多次模型调用，执行前应可见步骤数量及数据范围；沿用现有 DeepSeek 连接，不新增供应商。模型预算若需调整，由实现者据成果长度设有界配置并记录，不照搬旧短反馈的输出上限造成截断。

## 成果、纠正和记忆

- 成果版本不可无提示覆盖。用户提出纠正后建立有来源的新事实或修改指令，重新生成受影响成果；下游只能使用对应新上游版本。
- 显示各成果更新状态。上游成功、下游失败时保留两者历史，明确下游待更新，不能宣称全部同步。手动重试仅处理需要重做的步骤，避免重复已成功的调用。
- 纠正以用户明确表达为依据；模型推断单独标记。存在互相矛盾的资料时显示冲突或请求澄清，不静默改写用户事实。
- 事项事实仅用于本事项和有明确关系的后续步骤；长期偏好由用户主动保存，注明适用角色与范围，支持编辑或撤销。撤销不改写历史成果，也不能继续在新调用中引用。
- 后续相关运行实际读取最新有效事实与偏好，并保留引用快照。其他事项的私人资料默认不进入当前上下文。
- 本轮不承诺模型训练、自改代码或长期能力提升；“自我学习”通过可追溯反馈与用户可控记忆落地。

### 资料与记忆工作区（2026-09-27 已确认）

- 同页区分「事项资料」和「长期偏好」。桌面保留左侧列表与右侧详情；窄屏列表在详情上方，避免每件事项默认铺开全文。搜索仅对当前本地记录的标题、资料正文、纠正或偏好做关键词匹配，不称为语义检索。
- 事项资料仍属于原快捷或自定义 Agent 事项，不创建可被所有 Agent 默认读取的独立资料库。列表只收有文本资料或纠正的事项，可按两类事项筛选；详情显示 Markdown 正文、明确纠正的修订/有效状态及事项参与 Agent，实际资料读取仍依所属事项的权限，并能回到该事项修改。快捷纠正没有单条停用能力；自定义纠正的停用继续在所属事项操作。
- 长期偏好按 Agent 实例组织，预设与自定义实例使用同一浏览层级。每位 Agent 最多 5 条有效偏好；新建、编辑、撤销沿用原接口与并发校验，草稿按 Agent 隔离，切换页面后继续保留。撤销只影响后续运行，不改写历史快照。
- 旧版记忆只在有记录时提供原页面入口。空库展示真实空状态与创建/查看事项入口；不虚构待确认的模型推断、使用次数、资料验证状态或自动跨事项共享。

验收：隔离库中预设与自定义事项的资料和纠正可分别筛选、正文关键词可找到所属事项、无结果提示准确、两种来源跳转正确；预设与自定义偏好各可保存，切换 Agent 不串草稿，自定义偏好可编辑和撤销，团队页状态一致；桌面与 390px 可操作且无整页横向溢出。此项只验证资料管理 UI，不代表模型已自动记忆或个人内容效果。

### 资料与记忆二次重构（2026-09-27 已确认）

本节更新上述页面呈现，不改变事项、成果、偏好、Agent 权限或模型输入的持久规则。用户希望此模块更容易理解和使用；页面以“查找内容、核对来源、确定下一步”为主线。

- 将事项原始资料、用户明确纠正、当前可接续的已确认成果和 Agent 长期偏好作为不同内容类型。搜索是当前本地记录的关键词匹配，结果行显示匹配到的内容片段和所属事项或 Agent；没有独立文件上传、语义检索或自动提炼记忆。
- 原始资料与纠正始终归所属事项。快捷事项的纠正没有单条启停状态，不将每条旧纠正称为“有效”；自定义事项纠正的有效/停用状态来自真实记录。详情说明下一次使用范围与权限，并提供回原事项修改的操作，不暗示跨事项自动共享。
- 已确认成果即使原事项没有文本资料，也应能从此页找到。只把当前满足原接续条件的版本称为“可接续”，同时标出来源事项、产出 Agent 和版本。后续事项仍须由用户显式选择、预览和授权来源；历史成果和原始资料不能一键变成全局记忆。
- Agent 偏好区分有效与已撤销历史，显示所属 Agent。有效偏好可沿用原接口保存、编辑、撤销和冲突处理；撤销阻止未来引用，但不抹去旧运行快照。Agent 职责指令与长期偏好不同，不混成一条“记忆”。
- 空库不保留两块巨大的空列表/详情，给出从新建事项添加资料、核对成果的实际路径；桌面保留列表和右侧工作区，390px 可用且无全页横向溢出。

验收：隔离混合库覆盖资料、快捷/自定义纠正、无原始素材但有已确认成果、当前/历史版本、有效/撤销偏好；逐类筛选、关键词命中片段、来源和可使用范围准确，跳转到原事项及偏好操作可用；空库、桌面、390px 与键盘操作可达。不将 UI 可找回等同于模型自动学习或个人学习效果。

## 团队、状态与异常

- 复用内置三个持续身份的角色，共享运行底座但隔离上下文；团队页展示职责、参与事项、状态和资料边界。保留有限偏好配置，不增加外部 Agent 市场或任意代码构建器。
- 暂停立即阻止该角色新的执行步骤和后续重试；已开始的步骤显示真实状态，用户可取消。暂停期间迟到结果不能触发新的下游步骤。恢复不自动收费运行，由用户继续。
- 运行区分排队、执行中、等待用户、成功、失败、取消和中断等实际状态；角色可用不等于正在执行，生成成果不等于用户练习完成。
- 重复点击、并发请求与重试需要原子占用和幂等；取消、断连、改资料后迟到响应不能覆盖较新的事实或成果。
- 运行中修改资料/纠正时可阻止修改并提示先取消，或以版本冲突保护提交；不得让旧快照写成最新版本。实际选择在架构和验收中明确。
- 刷新不重复发起请求；进程重启将失去所有者的运行标为中断，不自动再次调用供应商。Key 仍只保留后端内存，重启后在页面重连。

## 时间与旧版兼容

用户可用时间用于核对、练习与复盘，Agent 的准备耗时独立呈现。生成时把本事项参与时间交给模型，使当次练习建议落在预算内；模型给出的具体时间仍需核对。可修改事项时间限制并对未完成的建议生效，保留旧成果和已发生记录；修改时间不会自动重写旧成果中的时间文字。旧版按日预算和练习反馈可以作为已有事项的历史/继续入口，不再成为新需求的强制前置步骤。

采用增量数据结构或无损关联，旧目标、任务、运行、反馈与记忆必须可访问，迁移不得伪造历史 Agent 交接。旧目标到事项的映射、旧导航的可达入口和恢复方式由实现前检查确定，写入实际架构。迁移幂等、事务化并先制作 SQLite 一致备份；先在隔离库及旧库一致副本验证，不使用重置、删除或重建用户数据库来通过测试。

| W7 | 桌面及窄屏走完入口、分工、成果、纠正、团队和记忆；主题互斥且独立恢复，草稿与状态不因切换丢失 |
| W8 | 时间约束可调整且反映在用户参与建议中；准备耗时不冒充用户已练习时间 |

自动化可用模拟供应商覆盖协议、失败与竞态，但需明确区分真实调用。真实生成仅用虚构验收材料；没有有效连接时如实记为待验证，不能索取用户 Key 到聊天、日志或命令行。当前授权不包含替用户投递、发送外部消息、扫描或批量上传本机资料。

## 非目标

本轮不增加移动/桌面客户端、社区交易、Agent 商店、外部 Agent 接入、任意流程画布、文件抓取工具、日历连接或全天后台自治。不改变本地开发、不使用 Git 和不公网部署约束。实施顺序及每块独立 QA 要求见[实施计划](../plans/mvp.md)。

## 快捷事项跨日接续（2026-09-27 已确认）

面试准备和词汇学习等连续目标可先排成多件事项，但排期本身不授权互相读取资料。用户在后一天快捷事项的右侧工作区明确选一件已确认成果作为来源，可选自定义 Agent 事项或快捷事项；保存前能预览来源。系统在保存时固定成果版本和内容。若来源是快捷事项，连同其已关联的来源链，以及该当前成果下最近一轮**已完成**练习的题目、实际作答、反馈与下一步建议，一起形成输入快照。未提交、失败或仅生成题目的轮次不算练习成果，也不补造进步。

关联和移除均需开放且未运行的目标事项，并校验目标修订和来源当前已确认版本；拒绝自我/循环引用。更新来源使目标的现有成果和练习退出当前状态，但保留历史及原运行输入；下一次生成和出题必须由用户手动启动。后续来源改动不静默改写已保存快照；若直接来源有新版，右侧提示当前仍使用固定旧版，用户可重新关联取新版。最多保留七段来源，过长时明确拒绝，不悄悄截断。只有具备上游成果权限的参与角色能接收这份来源；权限关闭时提示恢复或移除关联。

验收：七个隔离逻辑日各有面试与词汇事项，后续生成输入引用前一天明确关联的已确认成果；词汇的已完成练习反馈出现在次日生成与出题输入中。旧库迁移、陈旧来源、未确认成果、循环依赖、权限关闭和运行快照均有可核对结果。此场景只验证资料接续与模型输出，不代表真实学习效果或用户实际答题。

## 持续使用闭环（2026-09-26 已确认改进）

- 运行状态与事项生命周期分开。成果可逐一明确核对；事项可完成、归档、从历史重新打开。完成或归档不删除成果、来源和练习。运行中不得完成或归档；旧事项默认处于开放状态，旧成果仍待用户核对。
- 首页先显示需要操作的事项：待核对、待继续、失败和中断。显示原因与下一步，并提供完整事项列表入口。主动取消不自动列为告警；已完成或归档的事项退出待处理。
- 英语学习事项可在同一事项内开始练习、提交实际回答、得到引用回答的反馈，再进入下一题或次日继续。题目、回答、反馈和下一步依据分别保存；模型生成题目或成果不算用户完成练习，不宣称学习效果。一次性交付仍可使用。
- 资料、需求及明确纠正影响成果；参与时间和优先级只改变用户安排，不使已有成果机械过期。只修改英文要求时，仅英文成果及其依赖更新；中文事实或中文要求变化时更新中文和依赖它的英文。对无法确定影响范围的资料变化保守更新相关角色，保留版本与来源一致性。
- 已保存事项允许显式修改需求、角色、资料和参与安排。新增角色前显示会发送的事项需求、资料、纠正、适用偏好及上游成果；修改资料不自动新增角色。运行中修改受阻；移除角色不删除其历史，重新加入时按当前依赖判断有效性。
- 新版协调是系统规则编排，不是可独立暂停的模型角色；团队页不提供对新版无效的协调员开关或参与事项计数。旧版协调员暂停和偏好保持原有作用。
- 参与时间缩短时显示当前时间内可执行的核对、练习与取舍建议，说明规则依据；不假称模型已重新安排。运行完成通知应反映最新状态，状态及资料权限用用户可理解的文字展示。

持续使用验收：逻辑多日隔离 mock 页面覆盖完成退出待办后重开、两轮同事项练习与反馈、缩短时间后的成果保留、角色增减交接、暂停/受阻/失败/取消/重启显式恢复、偏好撤销、资料隔离及旧版历史。mock 只验证流程与数据，不代表真实模型质量。

## 独立复测后的有界交互修复（2026-09-26 已授权）

- 待处理练习按当前参与角色分别判断：只取每个角色最近一轮且来源仍是该角色当前有效成果的记录。反馈失败或中断、题目待答应在首页与详情写明角色和行动，不能被另一角色较新的已完成反馈遮蔽。旧成果来源或已移除角色的轮次保留为历史，不作为当前待办。主动取消不自动成为首页告警。
- 完成事项仍要求当前成果已确认，运行中仍不可完成。若当前角色还有待答、失败、中断，或已取消但留有题目/回答的练习，完成前明确列出并让用户选择继续处理或仍然结束；结束保留历史，重新打开后可继续。服务端在完成事务中核对页面所见的未完轮次，防止旧页面静默结束新出现的练习。练习可选，不因未完成而一律禁止结束事项。
- 暂停角色后，该角色练习的开始、提交回答和手动恢复在页面直接不可用，说明原因并提供团队页恢复入口；服务端继续校验角色状态。暂停期间仍可取消已在运行的练习，不隐式重新调用模型。
- 旧轮次来源失效时，若新成果尚未就绪，提示先更新成果；若新成果已就绪，说明旧轮次已保留、下一轮采用当前成果版本，不再提示用户重复更新。旧题不能作为新成果的有效待答。

验收以独立 SQLite 与 mock 浏览器复现为准：同事项一角色待答、另一角色反馈完成；一角色失败、另一角色反馈完成；完成时明确选择保留未完练习后重开；角色暂停后的开始/提交/恢复及取消；英文 v1 旧轮次在 v2 生成前后的两种提示。无新增 Agent 能力或真实模型效果结论。
