# 聚焦式工作区体验增量

> 状态：本轮用户确认「保留主体、利用右侧工作区、减少为找操作而连续下翻」；以下具体交互已实现，个人真实使用效果待验证。首页右侧摘要及事项/导航结构现由[一体化工作区规格](integrated-workspace.md)增量调整，本文件保留两类详情的主体与右侧工作区规则。
> 适用范围：新版工作台、两类事项详情、创建入口和 Agent 团队的信息顺序。底层事项、运行、权限与历史规则沿用[事项工作台规格](workbench-v2.md)、[创建 Agent 规格](agent-creation.md)和[日程规格](workspace-planning.md)。

## 问题与目标

当前首页同时展示待办、本周、完整建单表单、成果和最新事项；同一事项可能重复出现。快捷事项的「待回答」入口打开详情后，完成/归档、排期、分工和长成果先于实际题目与输入；自定义事项先出现修改步骤表单，再出现运行与成果。用户需要理解两类内部事项并不断下翻寻找下一步。

目标是让用户进入后先看见当前可执行动作，保留成果作为主体内容，右侧提供持续可见的事项上下文。长成果本身允许正常阅读滚动；寻找按钮和题目不应依赖穿过无关长区块。

## 页面与交互

1. 工作台首屏只突出一件需要处理的事项和一个「新建事项」入口；其余待办是紧凑队列。待办跨快捷事项和自定义 Agent 事项汇总，按截止/计划日期与最近更新排序，不先分两类。最近成果、本周与最近事项只提供简短摘要及明确去向，避免同一内容重复占据主体。
2. 新建先填写「要完成的事」，再展开必要配置。求职/英语预设建议可修改；使用自定义 Agent 时把已输入的需求带到对应编辑器，不要求重写。用户仍在保存/运行前核对参与者、资料范围、步骤和预计模型调用次数；页面不自动启动模型或扩大权限。
3. 已保存的快捷事项详情把「当前要做的事」置于主体顶部。待答时按题目、回答框、提交顺序展示；待核对时显示当前成果的确认入口；已有成果可开始练习时，开始或继续练习入口也在顶部，不必穿过完整成果。待开始、失败、中断、受阻时显示对应的明确操作或原因。完整成果、练习历史、纠正和修改仍可访问，旧版本保持可追溯。
4. 已保存的自定义事项详情先呈现运行状态、当前成果和可执行操作；失败时在主操作旁显示最近一次对应步骤的失败原因。修改需求、交接和步骤保留在次级编辑区；新建态仍以需求与步骤为主体。完成、归档、纠正、接续及运行来源继续可用。
5. 宽桌面采用「导航 / 主体 / 事项工作区」：主体显示当前动作和成果；右侧显示步骤状态、参与 Agent、排期、资料及历史入口。右侧可以独立阅读，但不抢占主体宽度。窄屏将事项工作区收为靠近标题的明确入口或折叠区，当前操作仍先于长内容；键盘可打开和关闭。
6. Agent 团队先展示创建入口与可用实例，运行指标和趋势移至次级区域。指标继续只统计自定义 Agent 事项，并在标题直接说明范围，避免快捷事项已有成果却看到全零时产生误解。

## 验收

| 编号 | 可观察结果 |
|---|---|
| UX1 | 桌面工作台首屏有唯一主待办和新建入口；同一事项不在首屏重复成多张长卡。两类待办同一队列，点击能进入对应详情。 |
| UX2 | 从「题目待回答」进入快捷详情，首屏可见题目、回答框及提交；从待核对/失败/待启动状态进入，可见对应动作。长成果不挡在操作之前。 |
| UX3 | 已保存自定义事项打开后先见运行/成果与下一步；编辑步骤需明确进入。创建和跨事项接续的完整授权表单仍可用。 |
| UX4 | 宽桌面右侧工作区承载真实事项上下文；窄屏仍可在靠近顶部处访问，主操作不因它下移。无横向溢出或键盘陷阱。 |
| UX5 | 新建先写需求，再配置预设或自定义 Agent；切换路径保留需求草稿，模型调用仍必须显式启动。 |
| UX6 | Agent 创建入口优先于指标；指标范围明确。旧事项、成果版本、纠正、排期、权限、草稿与模型运行控制回归可用。 |

## 边界与验证

本轮不合并两类事项的数据库表，不改模型提示、计费、权限和排期语义，不删除旧版入口或历史记录。使用隔离数据库和本地页面验证桌面、窄屏、键盘及刷新；真实个人使用后的疲劳感仍需用户试用评估。调研来源和采用理由见[UI 参考记录](../design/UI-REFERENCES.md#聚焦式工作区调研2026-09-27)。
