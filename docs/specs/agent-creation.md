# 用户创建 Agent 与平台调度

> 状态：已实现本地增量；N1—N5、NR1—NR4 定点修复、逐块及最终集成 QA 完成。已在本机原页面以虚构资料完成真实单 Agent、交接和纠正重试；个人实际效果待评估。
> 来源：2026-09-26 当前对话。用户暂不接入外部 Agent，先支持自己创建 Agent，平台保留规则调度；同时修复 UI，使用新任务和逐块全新 QA 策略。

## 范围与优先关系

这是[事项工作台规格](workbench-v2.md)的增量规格。新「Agent 事项」允许使用自建实例，求职、英语保留为可直接使用的预设和原快捷事项流程。旧版记录与专用练习继续兼容，其余成果、记忆、运行和数据保护约束沿用已有规格。实际实现与验收分别归架构、质量记录；任务状态只在[实施计划](../plans/mvp.md)维护。

产品目的是让用户创建持续存在的个人助手，把事情交给它，并能明确安排多位助手交接成果。新增 Agent 必须真正走通持久化、配置、执行、成果、控制和资料边界，不能只增加卡片或名称。

## 创建与管理

- Agent 团队提供明显的“创建 Agent”入口，可从空白配置或现有领域模板开始。保存后立即能在新事项中选择，不要求修改代码。
- 最小配置包括名称、职责/任务指令、预期交付物，以及可使用的资料与能力范围。每个实例拥有稳定标识、启停状态、配置修订及独立偏好；同模板创建的不同实例不能混淆记忆与历史。
- 本轮沿用共享运行底座与 DeepSeek 模型连接。实际能力限于已有、可执行的模型文本处理和显式资料交接；不得显示未实现的联网、任意文件读取、Shell、定时后台等开关。文字职责不能赋予系统权限。
- 配置可编辑，停用后不接新任务，恢复不自动运行。移除采用归档或停用保留历史；不提供永久删除已有记录的流程。
- 对自建实例，仅暂停或恢复不改变已生成成果的内容依据：开放事项里未改需求、资料、纠正、角色职责与权限的当前成果仍可查看、核对和完成。启停继续递增对外配置修订以拒绝陈旧编辑、取消运行中的结果，并阻止暂停期间的新步骤；恢复后尚未生成的步骤仍须手动继续。真正修改职责、交付物或资料权限仍使相关开放成果待更新。
- 编辑配置影响后续运行；已产生的成果和运行须保留当时的配置/名称来源，不能因改名改职责而改写历史。运行中配置修改和停用的竞态须在实施时明确并由后端保护。
- 输入长度、空值、重复名称的消歧、失效标识由前后端一致处理；展示名称不能作为数据库身份。

## 事项与调度

- 用户在事项中显式选择可用 Agent，单个 Agent 能独立执行，不能强制经过求职、英语或协调员。既有领域自动建议如保留，应可覆盖，不应阻止选择新 Agent。
- 多 Agent 协作先采用可理解的有序步骤：用户指定参与者、先后顺序和哪些已有步骤的成果交给后续步骤。用简单表单表达，不建设可视化流程编辑器或任意 DAG 平台。
- 运行前展示每步职责、交付物、可见资料与上游成果范围、预计模型调用数量。每步一次有界调用，不自动无限循环或收费重试。
- 平台调度机制负责状态、顺序、权限、暂停/取消、失败、手动重试及成果版本依赖。它不是可创建的“规则 Agent”，不伪装成调用模型的自主协调员；本轮不新增模型协调 Agent。
- 每一步使用所选实例的有效配置与授权上下文，返回由该实例负责的成果。交接记录准确的上游成果版本；上游失败/失效不得让下游继续冒用旧成果。改变参与者、步骤、配置或资料后的失效范围应清晰且有回归验证，保留历史。
- 继续支持事实纠正、成果核对、完成/归档/重开以及可控偏好；自定义实例的偏好不能进入无关实例。用户输入与模型生成内容不能改变平台强制的资料范围。
- 既有英语/求职专用练习须回归；不把所有新角色强制套进英语或面试练习。自定义角色首先完成事项交付与纠正闭环，不要求本轮重建通用教学系统。

## UI 与兼容

- 同一求职/英语预设在团队、快捷事项和自定义事项中的名称、职责、资料权限与有效偏好必须一致；旧偏好记录仍可见、可撤销，运行快照保留当时来源。关闭「事项文本资料与纠正」后，快捷成果和同事项练习的新请求也不得发送这些字段；关闭上游成果后，快捷英文步骤不得读取中文成果。新练习仅可引用同一当前成果及同一预设配置修订下的已完成旧轮，资料删除或权限收紧后的旧轮只能保留为历史。配置变更不得让旧运行迟到结果成为当前成果，并须即时结束本地正在运行的同角色快捷成果与练习状态；旧历史不改写。旧版专用练习保留其输入和操作边界，不因新配置而丢失原记录。
- 工作台的待参与、最近事项和「我的事项」覆盖快捷事项与自定义 Agent 事项；每条记录能进入对应详情。历史成果必须可从事项访问，即使执行步骤被移除、重排或替换；历史显示执行时角色、步骤和来源，不冒充当前成果。
- 切换自定义事项、返回新建、切换主题不丢失未保存的事实纠正；刷新/离页对未保存纠正给出提示。不同事项的纠正草稿不得串用。
- 团队页清楚区分可执行 Agent 与平台调度说明。创建、编辑、暂停、选择参与者和查看成果形成连贯路径；不暴露底层协议、内部字段或大量配置术语。
- 保留上一轮已修正的新版桌面左侧导航固定、右侧独立滚动、切页/换事项回顶部；同页输入、主题或数据刷新不意外跳顶。复验长创建表单、长成果、矮桌面及 390px 窄屏。小屏延续整页滚动。
- 明暗与主题色仍为互斥的两套模式，选择分别持久化；创建和编辑草稿遵守既有离开提示/保留规则。
- 旧版协调员记录、原英语与求职标识、旧事项、成果版本、练习和记忆不删除或重新生成。先在隔离库验证增量迁移和重复启动，再使用现有一致备份机制；恢复在副本验证，不覆盖原库。

## 验收

### PT 亲测修复行为（已实现，证据见验收记录）

- 每步将整事项作为背景，只交付本实例职责内的成果；不得因为总体目标同时包含中文整理和英文邀请，就让中文整理步骤代办英文步骤。步骤上下文不能扩大资料权限或暴露其他实例的私有指令、偏好。
- 实例保存的标题、分节、条数和顺序偏好可指导成果正文，不能改变 JSON 协议、纠正来源、职责或权限；条数限制应通过合并表达兼顾事实，不直接截断正文。当前采用提示与返回前自检要求，不提供任意自然语言格式约束的确定性保证。
- 纠正协议保留来源归属与成果证据校验，避免要求模型重复抄写整段来源才能通过。无效来源、重复/缺失来源、不属于正文的证据仍应拒绝；错误以不包含原始模型内容的明确诊断呈现，不自动收费重试，不改写历史。
- “资料与记忆”统一呈现快捷与自定义事项的资料、纠正和实例偏好，明确归属并可跳回对应事项；现有编辑/撤销能力跨入口保持一致，不能串用实例、吞掉草稿或覆盖陈旧修改。
- 暂停导致步骤无法继续时，就近显示具体助手、原因及前往恢复的入口；恢复后仍由用户手动启动。运行结束或受阻后不残留“运行已启动”的过时状态提示。
- 实例收紧上游读取权限后，已存步骤若仍有旧交接依赖，须明确显示配置冲突，不把未授权资料标为可见，也不允许无效继续。用户可自行取消旧依赖并保存，或回团队编辑权限；平台不自动扩大权限或改写步骤。
