# MVP 行为规格

> 状态：首版行为已实现；虚构数据的真实模型反馈与记忆引用已验证，个人场景效果待验证。
> 更新日期：2026-09-26
> 依据：已确认的项目范围，以及用户接受 v0.3 页面作为首版基线、后续逐步优化的决定。

2026-09-26 用户已认可新版事项工作台，新增行为与覆盖关系以 [新版规格](workbench-v2.md) 为准。本文件继续记录旧版兼容行为及被新版引用的连接、安全规则，不代表新设计已经实现。

## 问题与范围

草图使用预设数据，仅保留为设计材料。正式应用把导航、时间安排、练习反馈接到可追溯的任务、运行和本地记录；真实模型调用范围与结果见[验收记录](../quality/MVP-VERIFICATION.md)。

产品目标、角色职责、非目标与本地开发约束以 [项目定义](../PROJECT.md) 为准。本文件负责用户可观察行为及验收细化；不选择框架、模型供应商或数据库，不把草图中的求职优先、固定时长和示例答案写成产品规则。

## 已接受的界面基线

- 桌面优先的 Web 工作台，保留左侧导航：今天、目标、Agent 团队、执行记录。
- 今天展示可用时间、任务与参与角色；任务详情作为下级页面，保留全局导航。
- 目标关联任务；团队展示角色职责、状态与记忆；记录展示实际执行过程和结果。
- 沿用 [v0.3 草图](../design/workbench-wireframe.html) 的布局、密度、初始配色与响应式方向，后续有具体需求再迭代。接受界面不表示演示数据、固定反馈或所有运行语义已获批准。

### 主题规则

- 明暗主题提供固定浅色、深色两套配色，不自动跟随系统，不叠加彩色方案。
- 主题色是独立完整方案，首版使用雾蓝、松绿、暖棕；启用后收起明暗选项，不提供彩色主题的深浅变体。
- 顶部按钮切换模式；任何时刻只生效一套主题。默认深色，两套模式分别保留上次选择，切回时恢复。
- 切换作用于所有页面，不改变作答、任务状态、时间预算或未采用的安排。正式版本应在本地保存外观偏好，刷新后恢复。

| S2 | 请求生成今日安排 | 可查看领域角色的任务建议及协调员取舍；安排不超出用户给定预算；每项任务关联目标、负责角色与依据 | A1 |
| S3 | 修改时间预算并查看调整 | 展示调整前后任务内容或排期及原因；采用前保留原安排，取消不修改；采用后相关任务同步更新，已保存成果保留 | A3 |
| S4 | 进入任务并提交自己的回答或材料 | 空输入不能提交；处理中可见；反馈引用本次实际输入，保存任务、输入和结果之间的关联；模型不可用时明确失败，不以示例反馈替代 | A2 |
| S5 | 查看反馈并结束练习 | 反馈就绪与任务完成区分；结束后今天、团队与执行记录一致；失败不显示完成，重试仍能使用已保存输入 | A2、A5 |
| S6 | 采用训练建议，再执行下一次相关任务 | 记录建议来源，用户可查看和纠正；下一次使用相关记录并显示引用依据；不将一次推断直接当作能力事实 | A4 |
| S7 | 查看角色、调整有限配置并暂停角色 | 身份、职责、运行状态、可配置范围清楚；角色与单次运行分开；暂停对新任务及正在运行任务的影响须在实现前按下方未决项定义 | A5 |
| S8 | 刷新页面或重启应用 | 已保存目标、配置、输入、结果、记忆和主题偏好仍可恢复；未完成运行有真实状态，不假装成功；恢复细节见下方未决项 | A5 |
| S9 | 在练习中切换主题并切换页面 | 两套模式互斥且各自恢复上次选择；输入与任务状态不变；窄屏控件可操作，无页面横向溢出 | 界面基线 |
| S10 | 已完成测试任务后新增个人目标并安排今天 | 目标可以反复新建；用户可暂停某个目标参与后续安排，预览后才采用新计划；已完成任务与待办分开展示，完成的计划时长仍计入今日预算 | A1、A3、A5 |
| S11 | 完成练习、采用或纠正建议后再次预览 | 同一目标的新任务以已确认记忆、训练偏好和该目标的反馈建议改变练习方式；未采用的建议标明来源和临时性质，已采用或纠正的原建议不能重新标成未采用；与当前口语或写作方向冲突的旧要求不进入新任务或模型反馈；纠正记忆使旧预览失效 | A4 |

## 状态与信息边界

以下原则沿用项目定义及草图；具体存储字段、接口与状态枚举由后续技术设计确定：

- 用户需要参与的任务应显示等待用户，不能因为 Agent 已生成题目就标记任务完成。
- 模型反馈须引用本次作答中的真实连续原文；格式、引用、反馈正文或下次建议不合规则运行失败，任务详情展示可操作原因并保留作答。失败后只允许用户手动重试，不能自动增加模型请求或用预设内容补成成功。
- 英语反馈指令要求根据完整谓语与上下文核对时态；语法纠错须指出原文、最小修改与依据，并区分可选表达建议。正确表达应被认可，题目要求的总结或自我说明不能被作为偏题要求删除。此要求约束模型生成，不代表服务端已具备语法正确性判定能力。
- 单次运行至少能区分尚未执行、执行中、成功、失败；练习任务还需区分等待作答、反馈待查看和用户结束。
- Agent 角色持续存在，运行结束不删除身份和记录；角色暂停不是任务完成。
- 记录中能找到输入所属任务、参与角色、结果及反馈来源；示例数据与真实运行始终可区分。
- 共享可用时间、目标优先级和任务摘要；跨角色使用原始回答或个人资料需要明确范围，不能默认共享全文。
- 业务状态保存于本地 SQLite，主题偏好保存于当前浏览器；草图的内存状态不作为正式应用持久化方案。
- 日程协调员按目标优先级、剩余时间与用户设置的分配偏好生成确定性规则建议；这是首版协调逻辑，不表示协调员曾执行模型调用。
- 目标的“参与后续安排”开关默认开启；关闭后目标与历史任务仍可查看和编辑，已有待办在用户预览并采用新安排前保持不变，已完成或正在执行的任务不被移除。此开关持续有效，重新开启后可再次参与安排。
- 今天页优先显示待办及待查看反馈，已完成任务单独显示。已开始或完成任务的计划时长仍占用当日预算；要继续安排，用户需增加预算并预览、采用新安排。新增目标不自动生成任务。
- 首版用户通过目标参与状态、优先级、总时间和采用决定控制今日安排；具体练习题由规则生成，不支持手工新增或修改单项今日任务。
- 口语目标若允许文字转写，可先口头作答再提交转写文本；反馈只评价文字。“不练写作”本身不排除口语转写。明确要求纯语音且不接受文字输入的目标，预览中说明当前不支持，不生成相矛盾的写作任务。
- 首版用明确的口语、写作词及其附近的否定、暂停、独练表述判断练习方向；同一目标的题型、训练偏好和记忆引用使用同一判断。该规则不承诺理解任意自然语言；表述含糊时，用户可改写目标并重新预览。
- 同一目标的相关记忆按最近一次采用或纠正排序，最多引用五条；纠正旧记忆会使它成为最新要求，随后采用的新建议仍可更新重点。旧库中没有操作顺序的记忆沿用原创建顺序；纠正不会改写已有运行的引用快照。

## DeepSeek 模型连接

用户已确认首版供应商只包含 DeepSeek，鉴权使用 API Key。以下交互和凭据生命周期已实现；已用本机 Key 和虚构数据完成真实生成验证。

1. 在工作区提供“模型连接”入口，展示未连接、验证中、已连接和需重新连接的状态；不改变既有四个业务导航。
2. 通过密码输入框填写 Key，点击“连接 DeepSeek”后由本地后端验证；页面说明模型在云端运行，本次任务所需内容会发送到 DeepSeek。
3. 优先通过官方模型列表接口验证凭据并获取候选模型；列表成功只表示凭据及列表访问有效，不宣称余额充足或生成调用已经成功。
4. 选择当前可用且应用支持的 DeepSeek 模型。默认 API 标识 `deepseek-flash` 对应展示名 DeepSeek-V4.1-Flash；可选 `deepseek-v4-pro`。下拉菜单显示官方模型列表返回的展示名，并同时标出实际请求标识；旧连接缺少展示名时使用已核实的官方名称。名称依据见[官方核实记录](../architecture/OVERVIEW.md#deepseek-接口依据)；无兼容模型时显示原因，不使用虚构列表。
5. 三个角色初始共用所选模型与连接，但各自的身份、上下文、记忆和权限仍独立。切换模型影响后续运行，已开始的运行记录其原模型。
6. 提供替换 Key 与断开连接。新 Key 验证失败时保留原有效连接；成功后再替换。断开后禁止新调用，取消本地在途等待并丢弃迟到结果；已发给供应商的请求不保证撤销或停止计费。业务记录不因断开而删除。

### 数据与凭据边界

- 输入的 Key 仅用于本地后端请求 DeepSeek 官方地址，不写浏览器持久存储、URL、业务 SQLite、日志或模型上下文。成功后清空输入框，页面只显示连接状态，不回传完整密钥。
- 首版默认仅保留在后端进程内存，刷新页面可恢复连接状态，后端重启需重新输入 Key。界面明确这一行为；“记住密钥”及系统秘密存储集成不纳入本轮。
- 用户开始任务后，仅发送该任务明确提供的目标、材料、作答与相关且可追溯的记忆；不扫描本机文件、不上传整个数据库、不因连接验证而发送个人材料。
- 原始回答不会因共用 Key 自动跨角色共享。详细数据边界沿用项目定义；新增资料范围时须明确告知用户。
- 401、402、429、服务故障与网络超时分别呈现可操作的状态；401 要求重新连接，余额不足不伪装成密钥错误，不自动切到其他供应商。

### 连接验收

- 空 Key 在本地拦截；验证期间避免重复请求；失败结果和日志不得包含凭据、请求头或个人输入全文。
- 验证成功后候选列表只含兼容的 DeepSeek 模型；无凭据或断开时无法创建真实模型运行，但仍可查看本地记录。
- 使用两次交错的连接验证，较旧请求的响应不得覆盖更新的连接或断开状态。
- 检查刷新与后端重启的不同结果，以及替换失败保留旧连接、断开后迟到响应被忽略的行为。
- 模拟供应商响应可验证逻辑，但必须单独记录一次真实生成调用的结果，才可宣称 DeepSeek 已实际接通。

## 多渠道模型连接与 Agent 选择（2026-09-27 已确认）

本节覆盖上方首版“仅 DeepSeek / 三角色共用一个模型”的范围限制，保留原连接和旧记录。官方产品调研与设计推断见[模型管理调研](../design/UI-REFERENCES.md#多渠道模型与-agent-模型选择调研2026-09-27)。

1. 设置内可分别连接 DeepSeek、OpenAI、OpenRouter，或新建一个自命名的 OpenAI 兼容渠道。一个渠道连接配置对应一个 API Key；允许多个配置并存。现阶段仅接受 API Key，不提供通用账号登录；厂商登录 OAuth 须分别设计授权范围、回调、令牌续期与计费关系后再实施。
2. 新连接先请求该 Key 对应地址的 `/models`，显示返回的真实模型标识与展示名；列表缺失（404/405）时可手动填写模型标识，并标为尚未验证生成。列表验证不保证额度、JSON 输出能力或实际生成成功。自定义地址仅允许公网 HTTPS 基础地址，不接收 URL 中的凭据、查询参数、非标准端口和本机地址；页面提示 Key 会发送给该地址。
3. 工作区选一个默认渠道与模型；每位 Agent 可在团队概览中单独覆盖或恢复跟随默认。已存在的 DeepSeek 默认选择兼容保留。快捷事项、其练习、旧版反馈以及自定义 Agent 事项都按实际执行角色路由；多步事项在每一步启动时确定当时选择。切换不改历史运行和成果，也不自动将断开的渠道转到其他厂商。
4. 连接名称、基础地址、已取得的模型标识、默认选择和 Agent 选择存本机 SQLite `settings`；Key 仅在后端进程内存，刷新页面仍可用，重启后每条连接均需重新输入。替换失败保留原 Key；断开只清除该连接 Key、取消它的本地在途运行并保留配置及历史。已发出的供应商请求不保证停止处理或免计费。
5. 新渠道使用 Chat Completions JSON 输出协议；新版成果与练习通过 SSE 流式接收并在服务端校验最终 JSON，旧版反馈继续非流式。要求所选模型支持 `response_format: json_object`，新版运行还需支持流式响应。不支持的模型给出明确错误，运行保留为失败并由用户手动重试。现阶段不实现供应商专属 Responses 协议、非 OpenAI 兼容格式、本地模型发现、自动路由和自动降级。

验收：两个不同 Key 的 mock 渠道分别绑定两个 Agent，一项两步事项的请求必须发到两个对应地址并留下模型标识；断开一个不能取消另一个。配置、状态和运行记录不得含 Key。错误与过期选择不能静默回退；自定义私有地址在发送 Key 前拒绝。真实第三方渠道的模型列表、费用和生成能力在用户提供相应 Key 后再验证，不能由 mock 结果推断。

## 事项级模型选择（2026-09-27 已确认并实现）

用户要求自己的 Agent 能自由使用已连接的模型，并能在新建事项的需求输入框下直接选模型。本节是对上节路由的已实现增量；隔离验证范围见[MC2 验收](../quality/MVP-VERIFICATION.md#事项级模型选择隔离验收2026-09-27)。公开产品依据与本项目推断见[事项级模型选择调研](../design/UI-REFERENCES.md#事项级模型选择调研2026-09-27)。

1. 快捷事项与自选 Agent 事项的需求框下都显示同一语义的「本事项模型」。默认值为「跟随参与 Agent」，并就近显示当前预计的 Agent → 渠道/模型；没有参与 Agent 时显示工作区默认模型。设置页仍负责连接渠道和工作区默认值，团队页仍负责 Agent 的长期默认值。
2. 用户可以选一个已连接的具体渠道与模型，作为本事项的明确覆盖。选择器按渠道分组，显示模型名和真实 ID；手填模型标为「生成能力未验证」。在自选 Agent 路径中，首页已选模型随需求草稿带入事项编辑器，不因切换创建路径丢失。若有多个参与 Agent，明确说明本事项覆盖会用于全部步骤和后续练习/反馈；仍可选「跟随参与 Agent」让各 Agent 分别使用自己的模型。本轮不增加逐步骤模型表单或自动选模。
3. 路由优先级为「本事项明确覆盖 → 该 Agent 的模型 → 工作区默认」。跟随模式在每次实际启动步骤时读取当前 Agent/工作区设置；明确覆盖保存具体连接 ID 与模型 ID，后续运行继续用它。保存事项本身不调用模型。每次运行固定当次实际渠道与模型到历史记录；修改默认值或事项选择只影响尚未启动的调用，不重写旧成果，也不自动重新生成。
4. 选择器只列出当前已连接且在该连接模型清单中的模型；无可用模型时给出前往「模型连接」的入口。保存后的明确覆盖若断线、被移除或模型不再可用，详情保留原选择并显示阻塞原因，启动时拒绝请求；不静默改用 Agent/工作区默认或其他供应商。模型列表存在不代表该模型支持当前 JSON 输出协议，实际生成失败按现有错误与手动重试规则处理。
5. 事项选择只存连接和模型标识，不存 API Key。用户编辑已保存事项的模型选择时应有并发修订校验，正在运行时不可更改；这次修改不扩大资料权限，也不使已确认的旧成果失效。详情与启动前须能看见下一次调用实际会用的模型，尤其是多 Agent 接力时的下一步。

验收目标：同一隔离库中，一件快捷双角色事项默认按两个 Agent 的不同模型运行，另一件自选双步骤事项选择单一事项覆盖并两步命中该模型；练习/反馈也遵从事项覆盖。测试切换默认值、重启后的 Key 断连、手动模型、失效模型、历史快照和并发修改。使用合成 Key 与 mock 渠道验证路由，不把它当作第三方模型生成质量的证据；测试数据按[一次性测试约定](../operations/RUNBOOK.md#一次性测试数据)清理。

## 运行与重排规则

- 保存草稿是显式操作；页面切换保留当前未保存输入，刷新后只恢复已保存草稿。提交时也保存本次输入。
- 相同提交标识和相同输入重复请求返回原运行，不再次调用模型；失败、取消或中断后由用户主动重试，产生新的运行记录。
- 暂停领域角色阻止该角色的新运行与新安排；暂停协调员阻止预览和采用新安排。单次取消终止本地等待并保持取消状态；供应商已接收的请求不保证撤销或免计费。
- 重启后仅把失去进程所有者的运行标记为中断，保留输入并允许手动重试；不会自动再次调用模型。Key 只在后端内存中，重启后需重新连接。
- 重排预览显示调整前后的任务与依据；采用时仅替换当日未开始或可重试任务。已运行、待查看反馈及完成任务占用预算，预算不足时拒绝采用。旧任务和草稿仍在记录中，不自动套用到新题目。
- 角色可修改启用状态和训练偏好；协调员可选按优先级或均衡分配。共享摘要与时间预算，领域记忆只在所属目标与角色的后续运行中引用。

真实用户材料的效果、额度和调用成本仍需在个人场景中核实；虚构数据的真实模型调用证据见[验收记录](../quality/MVP-VERIFICATION.md)。
