# Agent 管理与跨事项接续规格

> 状态：2026-09-27 用户已确认方向，功能已在本地实现并通过隔离测试、页面走查与独立 QA；个人真实使用效果待评估。本文是本次增量的行为真源；现有创建、执行和权限规则仍见[创建 Agent 规格](agent-creation.md)。

## 产品目标与边界

个人需要回答三个问题：今天哪些事要我处理；每位 Agent 最近实际做了什么、交付了什么；下一件相关的事如何沿用已经确认的成果。总览服务个人决策，不做企业运维控制台。求职和英语只是实例，所有自建 Agent 应适用。外部 Agent、后台自治、跨事项自动读取、精确费用统计不在本次范围。

现有快捷事项与自建 Agent 事项是两条数据链。新团队指标先明确标注为“Agent 事项”，不能暗示已统计快捷事项；工作台待处理仍覆盖两条链。没有实际记录时显示“尚无记录”，不预填演示数字。

## 页面草图与行为

```text
工作台  [需要我处理的事项] [最近成果] [前往 Agent 团队]
Agent 团队  [选择 Agent]  |  [选中 Agent 概览：交付 / 职责 / 权限 / 偏好 / 创建事项]
  [创建 Agent：空白或模板]  [编辑配置]  [暂停/恢复]
  [查看事项与历史：近 7 天指标 / 参与事项 / 时间倒序事件]
  [团队运行统计与趋势：按需展开，明确仅统计 Agent 事项]
事项详情  [以这份已确认成果新建后续事项] → 选择目标标签、参与 Agent、可见来源 → 保存
```

- 团队列表保留创建、编辑、暂停/恢复。详情可返回团队并打开关联事项；运行历史及成果有明确状态和时间。
- 团队默认选中第一位 Agent，桌面列表与概览并列；窄屏横向选择后显示同一概览。切换实例只改变当前上下文，长期偏好和未保存新增偏好按实例隔离。已有配置草稿在切换或返回时保留；创建可从空白或模板开始。内置预设即使没有自定义 Agent 事项指标，也可进入概览、编辑和历史空状态。
- 从选中实例“创建事项”会预选该 Agent 为第一步；若已有未保存事项草稿，保留原草稿并提示用户先处理，不静默覆盖。暂停实例不能从该按钮进入新事项，恢复不自动启动模型。统计和趋势默认收起，仍可展开并按原有真实口径下钻。
- 近 7 天采用本机当前时刻往前 7×24 小时的窗口；时间显示按浏览器本地时区。参与事项数按窗口内运行涉及的不同事项计；成功/失败分别按终态运行计，不把运行成功称为用户目标完成。已确认成果按确认时间计，重复确认不得重复计数。暂停不删除历史。最近活动取真实运行或成果时间；没有运行时显示“尚未运行”。
- 工作台只展示可行动待办和最近成果的少量摘要，数字的精确口径在团队页。失败、待确认与已完成应分开。点击数字或行能看到对应记录；不允许只有装饰性统计。
- 单 Agent 详情显示该实例参与过的自建事项、运行结果、失败原因的安全摘要、成果版本、用户确认状态和来源。历史角色名/配置取执行快照，不因当前配置变化改写。
- 团队指标下钻、单 Agent 事件和参与事项按页加载；继续查看时固定首次读取的时间与事件序号高水位，使用时间与记录 ID 游标，避免同秒新运行或状态变化混入旧页、重复或遗漏既有记录。数量仍按固定窗口的完整记录计算；页面明确区分当前成果与历史版本。

## 明确接续与权限

- 用户从某份**已确认**的自建事项成果主动发起后续事项；先看到来源事项、Agent、成果版本及将发送的内容摘要，再选择新事项的 Agent 和可选的目标标签。来源记录采用不可变的成果 ID/版本，不能静默改为该事项的最新版。
- 新事项只读取用户所选的成果，不读取来源事项的其他资料、纠正、偏好或历史成果；仍按接收 Agent 的 `allow_upstream` 权限执行。权限收紧后，新运行不得继续读取旧授权来源，应明确提示重新选择或调整权限。来源本身不因新事项完成而改变。
- 目标标签只用于用户组织相关事项；不触发资料共享，也不代表自动判断学习进步。空标签允许存在。后续事项可再次以自己的已确认成果接续，形成可追溯链，不能形成自引用或循环。
- 修改或取消接续必须明确操作；已生成运行保留当时的来源快照。来源被归档仍可追溯。没有已确认成果时不显示可执行接续按钮，而是引导先核对成果。

## 验收

| 编号 | 可观察结果 |
|---|---|
| AM1 | 空库只显示真实空状态，团队指标为 0 或“尚未运行”；不产生假数据。 |
| AM2 | 两个 Agent 在不同日期参与多个事项后，团队 7 日口径、单 Agent 时间线、事项跳转与原始记录一致；成功、确认、完成不混同。 |
| AM3 | 暂停、失败、重试及配置改名后历史不丢失、不变名；窗口外运行不计入 7 日汇总。 |
| AM4 | 用户从已确认 v1 成果创建后续事项，运行只读取选定 v1；来源更新到 v2 后不会静默替换，目标标签不分享资料。 |
| AM5 | 接收 Agent 无上游权限、来源无确认成果、陈旧或伪造来源、并发修改时，后端阻止越界或覆盖；旧事项和成果不受损。 |
| AM6 | 桌面及窄屏完成工作台→团队→Agent 详情→事项→后续事项路径；刷新、重启后关联与历史仍可见。 |
| AM7 | 团队首屏能直接选中实例并查看职责、权限和该实例偏好；空指标不禁用内置实例的管理入口。桌面和 390px 可创建、编辑、切换、查看历史及按需打开统计，切换时不串用偏好或覆盖已有事项草稿。 |

使用隔离数据库和虚构资料验证；mock 证明状态与数据范围，真实模型效果另行记录。迁移前一致备份，失败时不写入半成品；不在用户当前业务库制造验收数据。
